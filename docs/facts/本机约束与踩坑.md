## 二、三个结构性技术风险

1. **系统缩放 125%**：物理 1920×1200 但程序看到 1536×960。所有定位按逻辑像素算，测试时 100% 与 125% 都要看。
2. **Windows 11 自动圆角裁剪**：DWM 可能给无边框窗口切角，导致自绘圆角变形，需显式关闭。（当前实测透明窗口下未观察到裁切，条款保留。）
3. **鼠标穿透**：窗口是矩形，透明区域的鼠标事件仍归窗口。已决策不做穿透，见 `docs/facts/技术方案.md` 决策记录。

## 三、踩坑记录

### 启动与环境

- **`ELECTRON_RUN_AS_NODE=1`**：DSH 运行环境全局设了该变量，直接跑 `electron.exe` 会被当纯 Node（`TypeError: Cannot read properties of undefined (reading 'whenReady')`）。启动前必须 `Remove-Item Env:ELECTRON_RUN_AS_NODE`。用户双击/正常终端启动不受影响。
  - **打包版同样受影响**：症状不是 whenReady 报错，而是秒退 + 报 `bad option: --hidden`（Node 把 electron 开关当 CLI 参数），极易误判为安装包坏了。
- **electron postinstall 不跑**：DSH 沙箱下 `npm install` 后 `node_modules\electron\dist\` 缺失，需手动 `node node_modules/electron/install.js`。
- **清理类 e2e 绝不能碰回收站（2026-11-20 事故）**：在隔离实例里测「系统垃圾」清理时，探针脚本用「反选所有未勾选项」的方式勾选，把默认不勾的**回收站**一起选上并点了清理，`Clear-RecycleBin` 当场清空真实回收站（1.27 GB，不可恢复）。隔离实例只换了 userData / APPDATA / TEMP，**回收站、Windows 更新缓存、WER 都是系统共用的真东西**。规则：自动化清理只按 id 精确勾选；回收站与所有「需要管理员」项在测试里一律不点；提权的删除逻辑要么不测，要么用假目录单独跑脚本层。
- **安装版与预览版不要同时开着（用户 m01401 明确要求）**：安装版（`D:\软件\灵动岛\灵动岛.exe`）与开发预览版（`node_modules\electron\dist\electron.exe .`）都叫「灵动岛」、都置顶、都读同一份 `%APPDATA%\lingdong-island\` 数据，同时跑会出现两个岛重叠、托盘图标重复、钩子抢焦点，而且 `Get-Process 灵动岛` 会混在一起分不清哪个是哪个（曾导致 CDP 探针量到用户自己那个实例的窗口矩形、坐标全错）。起预览版前先 `Get-Process 灵动岛 -ErrorAction SilentlyContinue | Stop-Process -Force`；起安装版前先杀光 `electron` 进程。
- **下载/打包镜像**：electron 与 electron-builder 都直连 GitHub 会超时或报 `unable to verify the first certificate`。打包前必须同时设：
  ```powershell
  $env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
  $env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'
  ```
- **打包命令（2026-11-17 实测）**：`npm run dist` 会因下载 electron 报 `unable to verify the first certificate`；即使设了镜像，默认压缩级别也会让 electron-builder 调起的 `7za.exe` 报 `ERROR: Can't allocate required memory!`（exit 8），而同样参数手工跑 `7za` 却成功。可用命令：
  ```powershell
  npx electron-builder --win -c.electronDist=node_modules/electron/dist -c.compression=normal
  ```
  `-c.compression=normal` 是关键（`--config.compression=normal` 这种写法不生效，日志里仍是 `-mx=9`）。代价是安装包体积略大，功能和内容无差别。
- **直推 GitHub 超时但 API 正常（2026-11-19 实测）**：本机 DNS 把 `github.com` 解析到 `20.205.243.166`，443 握手 20 秒超时；同一时刻 `api.github.com` 返回 200、`gh` 正常，`140.82.112.3` / `140.82.113.3` / `140.82.114.3` / `20.27.177.113` 的 443 都通。不要改 hosts（系统级、影响面大），按次绕过即可：`git -c http.curloptResolve=github.com:443:140.82.112.3 push origin main`；`curl` 加 `--resolve github.com:443:<IP>`。
- **提权跑 `.ps1` 用 `-EncodedCommand`，别用 `-Verb RunAs -File`（2026-11-19 实测）**：`Start-Process powershell -Verb RunAs -ArgumentList '-File','...ps1'` 对无 BOM 的 UTF-8 脚本（`Write` 工具默认写法）静默失败——`ExitCode=1`、脚本一行没执行、连第一条日志都没写；UAC 是正常通过了的，容易误判成「权限不够」。同一脚本改成 `iconv -f UTF-8 -t UTF-16LE | base64 -w0` 后传 `-EncodedCommand`，一次就成功。需要看输出时让脚本自己写日志到 `$env:TEMP`（提权后 `$env:TEMP` 仍是同一用户目录）。

### 渲染与交互

- **程序化截图必须先 `SetProcessDPIAware()`**：125% 缩放下，非 DPI-aware 进程的 `CopyFromScreen`/`GetWindowRect` 返回 0.8 倍虚拟坐标，截图裁剪会错位。（⚠️ 2026-11-09 订正：本条最初的推论「展开态残影=截图伪影」**是错的**，见下一条。DPI 坑本身真实存在，截图工具链仍须遵守。）pwsh 每次执行命令都是新进程，`SetProcessDPIAware()` 必须在该进程任何 GDI/user32 调用之前调用，存在时序竞态——同一脚本有的进程生效有的不生效。可靠路线：单会话内 `SetProcessDPIAware` + P/Invoke `DwmGetWindowAttribute(hwnd, DWMWA_EXTENDED_FRAME_BOUNDS=9)` 取真物理 rect + `BitBlt`（纯 GDI）截图；`GetPixel` 在 **gdi32.dll** 不在 user32。`PrintWindow(PW_RENDERFULLCONTENT)` 抓窗口自身 surface 可作对照。

- **展开态「残影」真因：面板背景 3% 透明度，不是 DWM 丢行（2026-11-09 订正 670c9e4 的错误结论）**：用户报告展开面板中部透出下层窗口内容（红横幅/白字），先误判为「动态 setBounds 后 DWM 不重绘新增区域」（与横幅坑同族），又误判为「截图伪影」。最终用**红色诊断法**实锤：`.island` 背景临时改 `rgba(255,0,0,1)`，BitBlt + GetPixel 逐点采样整个展开窗口全部为纯红、零丢行 → 「DWM 丢行」理论证伪。真因：`.island` 背景 `rgba(9,9,11,0.97)` 只有 97% 不透明，下层 DSH 的亮色内容（红横幅、白字）以 3% 权重透上来，DSH 内容越亮越明显。这是**正常 alpha 合成**不是 bug；若嫌碍眼把背景 alpha 改 1.0 即可（视觉几乎无差）。排查中还排除了：GPU 合成（`--disable-gpu` 下残影仍在）、补间动画连发（固定窗口尺寸、等 4 秒后截仍复现）。

- **透明置顶窗上做「真模糊」只有抓屏一条路（2026-11-24 实测三轮）**：① `backdrop-filter: blur()` 在透明 Electron 窗口里只采样同一页面内绘制在下方的内容，桌面原样清晰透出，加了没用；② Windows 的 `backgroundMaterial: 'acrylic' | 'mica'`（含运行时 `setBackgroundMaterial`）加在 `transparent: true` 的窗口上，窗口会变成一整块不透明灰板，透明和模糊都没了；③ 可行路径是 `desktopCapturer.getSources({types:['screen'], thumbnailSize})` 抓整屏再按窗口 bounds 裁。**抓之前必须 `win.setContentProtection(true)`**，否则会把岛自己拍进底图；开保护后同一进程立刻抓屏不会拍到该窗口（WDA_EXCLUDEFROMCAPTURE 生效，实验 `.tmp/glass-probe/capture.js`），抓完 `finally` 关掉。耗时：缩略图 35% 全屏时单次 116–183 ms（渲染层视角含 IPC 往返）。注意副作用：保护开着的那 ~150 ms 里，**屏幕共享/录屏的观众看不到岛**，高频抓取（展开态 1.5 s 一次）会表现为闪烁。
- **preload 里没有 window/DOM**：跨上下文通知不能用 `window.dispatchEvent`；也不要用 `ipcRenderer.emit/on` 做进程内广播（emit 第 2 参会落在监听器第 1 参上，曾致 `setItems(undefined)` 白屏）。用模块级回调数组。
- **React 19 合成鼠标事件**：e2e 触发 `onMouseLeave` 收岛必须派发 `new MouseEvent('mouseout', { bubbles: true })`，合成 `mouseleave` 无效。
- **HTML5 拖动换位**：`dataTransfer` 里必须有 `setData` 数据，Electron 下 dragover/drop 才稳定触发；React 处理器要用 `setItems(prev => ...)` 函数式更新，避免连续拖动拿到旧列表。
- **连续换位偶发失效**：换位后以主进程 `shelfReorder` 响应为准，IPC 慢响应会乱序覆盖，用模块级 `reorderSeq` 序号只采纳最新响应。换位语义用**互换**（拖 A 到 B 两格互换），「插到目标后面」不符合直觉且前后向不对称。
- **格子拖动处理器必须区分内部/外部拖放**：`onDragOver`/`onDrop` 只在 `reorderFrom.current !== null` 时 `stopPropagation`，否则外部文件拖到格子上被吞（🚫 光标、放不进去）。
- **`onDragEnter` 必须去重**：冒泡每划过一个子元素重复触发，反复 `gotoPage` 重挂页面重放动画 = 频闪抖动；`dragActive` ref 一次拖动只处理一次（dragleave/drop 复位）。
- **拖文件进窗口会触发 Chromium 导航**：已在 `src/main/index.ts` 用 `will-navigate` preventDefault 拦截。
- **性能**：`.island` 不要常驻 `will-change: width, height`（只在动画进行中临时用）。交互反馈动画 ≤ 200ms。
- **`prefers-reduced-motion`**：已支持，停岛仔/眼睛动画、勾选弹跳，过渡降为 1ms。
- **file:// 来源的 localStorage 跨进程重启丢失（不持久化）**：2026-11-06 US-032 实测——SIGTERM 强杀与 CloseMainWindow 优雅退出后重启，`localStorage.getItem` 读回 null；同进程 reload 则有效。需要跨重启保留的数据一律存主进程文件。受此影响的两处现行实现都已迁到 `prefs.json`：页面自定义（US-032，2026-11-06）与置物架视图记忆（US-035 早期误用 localStorage，US-037 于 2026-11-07 迁移）。旧「仍用 localStorage / 待另开故事修」的附注已作废，现行规则见 `docs/facts/数据规则.md` 第 5 条。

### 布局

- **`max-content` 被压扁**：`.island` 是 flex 容器的子项，默认 `flex-shrink: 1`，必须先 `flex-shrink: 0` 才能撑开。
- **`.page-fade` 不能全局 `width:100%`**：与日程页 `max-content` 互锁。只有第 2/3 页加 `.page-fade.wide`。
- **靠右/居中类布局必须在空态（最小内容）下验证**：`.page-fade` 无宽度约束时宽度=内容自然宽（空置物架 210px、空通知 143px），工具条 `width:100%` 只到这个宽度，按钮悬在中间——这是第五轮结论被推翻的原因。
- **头部布局（2026-11-18 起两行）**：第一行 `.head-top` 放徽章/标题/岛仔/完成度，第二行 `.head-status` 在正常流里整行居中；状态区不再绝对定位。第一行仍靠 `panel-head-spacer`（`flex:1`）把右侧元素推到右边，**不要**给右侧元素加 `margin-left:auto`。历史教训：`position:absolute; left:50%` 的居中盒可用宽度只有半个面板，宽内容（如 `dateWeek` 档时钟）会折行并压住左侧标题——居中块里放会变宽的内容前先量 `scrollWidth`。
- **grid auto-fill 在 max-content 容器里算不出列数**：置物架图标视图改 `flex-wrap: wrap` 才不塌成一列。

### 系统能力

- **Electron 32+ 没有 `File.path`**：拿拖入文件路径用 preload 里的 `webUtils.getPathForFile(file)`。
- **系统图标提取**：Electron 无内置 API。文件夹/文件按真实路径走 `SHGetFileInfo`（PowerShell P/Invoke 脚本 `icon-cache\extract-icon.ps1`），普通文件可按扩展名造样本走 `ExtractAssociatedIcon`；结果 PNG 缓存 `userData\icon-cache\<ext>.png`（文件夹 `_folder.png`）。**首个扩展名首次提取可能超时暂显 SVG**，第二次命中缓存即正常（出现频率未验证）。
- **Electron 45 异步剪贴板**：`clipboard.readText()` 返回 `Promise<string>`，主进程轮询要 await。`app.getLoginItemSettings()` 不接受位置参数。
- **Electron 45 开机自启**：`get/set` 按「exe 路径 + 启动参数」匹配注册表，必须传同一 args（本项目 `AUTOSTART_ARGS`）。**且 args 必须含 app 绝对路径**：相对路径 `'.'` 开机时工作目录是 `C:\WINDOWS\system32` 解析不到（报 `Unable to find Electron app at C:\WINDOWS\system32`）；裸 exe 会弹 Electron 默认欢迎页。最终方案 `args: [join(__dirname,'..','..'), '--hidden']`。
- **asar 内 `__dirname`** 指向 `resources\app.asar\out\main`——打包版自启 args 走 `app.isPackaged` 分支只带 `--hidden`，开发版才补 app 路径。
- **通知库读取**：`%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db`，复制 db+wal+shm 三件套后 `node:sqlite` 只读。大整数列必须 `CAST AS TEXT`；FILETIME→ms：`Number(t)/10000 - 11644473600000`。
- **电量**：无桌面会话或无电池时 `Get-CimInstance Win32_Battery` 返回 null，UI 自动隐藏。
- **充电判定别用 `BatteryStatus -eq 2`，也别死守 `6/7/8/9`（2026-11-09 三次实测踩坑）**：`Win32_Battery.BatteryStatus` 的 `2` 是「接着交流电但没在充电」、`3` 是已充满、只有 `6/7/8/9` 才是微软语义的「正在充电」。踩过两个反方向的坑：①旧代码用 `-eq 2` 判充电，等于把「插着电」当「在充电」——本机插电、96%、`ChargeRate=0` 时输出 `96|True`，界面本不该绿；②改成只认 `6/7/8/9` 后又漏判——同一台机器电池到 96% 后系统停止充电仍在供电，`BatteryStatus` 停在 `2`，于是显示白弧，用户 17:37 原话「我现在冲着电，他是白的」。**用户口径是「插着电源就是充电态」，不是微软的充电状态机**，所以最终判据取「不是放电态」：`(($b.BatteryStatus -notin 1) -and -not [bool]($w|Where-Object {$_.Discharging}))`，同机输出 `96|True`。**第三个坑（独立验收 C3 发现）**：`4/5`（低电/临界）不能排除——插着电且电量 ≤20% 时必须走绿（充电优先），排除 `4/5` 会让「插着电 + 15%」错走红态。**同族坑**：`root\wmi` 的 `PowerOnline`、.NET `SystemInformation.PowerStatus.PowerLineStatus`、`GetSystemPowerStatus().ACLineStatus` 都只表示「插没插电」，单独用都判不出充电。四种判据实测差分见 `docs/Spec/SPEC-battery-charging-accuracy.md` 第九节。
- **拔线后系统仍可能报「接着 AC」（2026-11-09 实测）**：用户拔掉电源后，`powercfg /batteryreport` 的 Recent usage 末条仍记 `AC`、`GetSystemPowerStatus().ACLineStatus` 仍是 `1`、`Win32_Battery.BatteryStatus` 仍是 `2`。这种情况下任何「插电判定」都会继续显示充电态，软件层判不干净。排查顺序：先跑 `powercfg /batteryreport` 看系统到底认为接没接电，再怀疑代码。
- **Web 电池 API 在 Electron 45 已移除（2026-11-09 实测）**：`typeof navigator.getBattery === 'undefined'`（electron 45.2.1 / chrome 156.0.8078.75）。想在渲染层直接拿电池事件是走不通的，必须走主进程 `powerMonitor`。
- **`powerMonitor` 可用，但事件不保证来（2026-11-09 实测）**：`powerMonitor.on('on-ac' / 'on-battery' / 'resume')` 与 `isOnBatteryPower()` 都正常存在（注册成功、调用有返回值）。但本机探针以 2 秒间隔连跑 600 秒（`.tmp\powermonitor-probe.log`）**一个 `on-ac` / `on-battery` 都没收到**——期间用户确实没插拔过，所以既不能证实也不能证伪「本机发不发这个事件」。因此刷新链路必须自带兜底：`isOnBatteryPower()` 1 秒看门狗（`WATCH_MS = 1_000`，早期版本曾设 2 秒）+ 保留原来的 30 秒缓存 / 60 秒轮询。
- **别高频 spawn PowerShell（2026-11-09 实测）**：同一个探针以 2 秒间隔反复起 `powershell.exe` 查 CIM，90 秒后开始间歇报 `Failed to create CoreCLR, HRESULT: 0x8007000E` 与 `Failed to load System.Private.CoreLib.dll ... Out Of Memory`。电量取数保持「低频 + 事件驱动」，不要改成几秒一次的轮询。另注：PowerShell 冷启动一次约 0.3 秒（电量行）/ 1.0 秒（电量+网络两行合并），慢在进程启动不在 CIM 查询（同进程内查 10 次仅 150–250 ms）。
- **PowerShell 输出按系统代码页编码，中文报错会变乱码（2026-11-20 实测）**：`powershell.exe -Command` 的 stdout/stderr 在中文系统按 GBK 写出，Node 按 UTF-8 解码就得到一串 `�`，行号、命令文本、报错提示全混在一起。在脚本前拼一句 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8;` 后再执行，输出即为 UTF-8（实测 `throw "测试中文错误"`：不加前缀是乱码，加了是完整中文）。`runPowerShell` 已统一加这个前缀，`runCommand`（`reg.exe` 等）不受影响。
- **回收站为空时 `Clear-RecycleBin` 会报错（2026-11-20 实测）**：回收站里 0 个条目时执行 `Clear-RecycleBin -Force`，抛 `System.ComponentModel.Win32Exception: 系统找不到指定的文件`，错误 ID `FailedToClearRecycleBin`，不是真的没清掉。清理前先数条目数，为 0 直接跳过；清理报错后再数一次，空了就算成功。
- **插拔电源后最长约 90 秒才刷新（2026-11-09 晚已修）**：旧链路是主进程缓存 30 秒 + 渲染层 60 秒轮询，改判据只修对错、不改延迟。现在主进程监听 `powerMonitor` 事件，事件到达后 600 ms 重读并 `webContents.send('island:status-changed', snapshot)` 推给渲染层，插拔电源约 1–3 秒变色；30 秒缓存与 60 秒轮询保留作为最后兜底。SPEC 见 `docs/Spec/SPEC-battery-status-push.md`。改判据或改刷新逻辑后立刻验证要重启应用（主进程缓存跟着重置）。
- **SMTC 音乐会话的四个坑（2026-11-11 实测，音乐页开发时逐个踩到）**：
  1. **`.ps1` 必须 UTF-8 带 BOM**（`EF BB BF`）。不带 BOM 时 PS 5.1 按系统 ANSI 解码含中文的脚本，`[System.WindowsRuntimeSystemExtensions]` 会报「找不到类型」。
  2. **PowerShell 函数不能把 WinRT 对象当返回值传出去**：调用方拿到的是丢了类型投影的代理，再调 `GetPlaybackInfo()` 抛 `System.ArgumentException: 对象的类型不能为 Windows 运行时类型`。解决办法是函数只返回 **int 索引**，快照在调用方同一作用域内联取。
  3. **`$mgr.GetSessions()` 返回的是 `System.__ComObject` 包装的 WinRT `IVectorView`，裸索引只有 `[0]` 有效**：`$sessions[1]` 及以后一律 `$null`，必须写 `@($sessions)[$i]` 才安全。单会话时 `[0]` 恰好命中，本地极难发现；用户同时开两个播放器、正在播放的不在索引 0 时，界面恒为「现在没有在放歌」。回归脚本 `scripts/e2e-music-session.mjs` 专门造这个场景。
  4. **异常不要吞**：poll 时把异常静默换成空态，会让人误判成「本机没有播放器」。现在 `catch` 里 emit `{type:"error",msg}`，Node 侧 `console.warn` 出来。
  另注：`PotPlayerMini64.exe` 进程退出后会话立刻消失，任何「探针能读、产品读不到」的对比都必须先 `tasklist` 确认播放器在跑、并让两边同一时刻跑。
- **~~PS 5.1 拿不到 SMTC 封面字节、音乐页不做封面（2026-11-11 结论）~~ 本条 2026-11-15 作废**：原记录是 `props.Thumbnail` 非 null（`RandomAccessStreamReference`），但 `OpenReadAsync()` 返回 `System.__ComObject`，转 `IRandomAccessStreamWithContentType` 后 `Size`/`ContentType` 全空；`DataReader`、PS 直接 `AsStreamForRead` 两条路报转换失败；`Add-Type -TypeDefinition` 编译 C# 吃不下 `WinMetadata\*.winmd`（`CS1701`/`0x80131047`），`csc.exe` 报 `CS0012` 缺 `System.Runtime 4.0.0.0`，本机没有 `.NETFramework\v4.x\Facades` 引用程序集 ⇒ 当时结论「用音符占位，不做封面」。
  - **正确做法（2026-11-15 第 2 批 `.tmp/probe-cover-art2.mjs` 连跑两次实测，[已核验]）**：这些失败只证明「不能编译期引用 `.winmd` / 不能把 `__ComObject` 强转」，没试「从已加载程序集反射并传原始对象」。`AsTask` 反射用的是同一程序集 ⇒ `System.Runtime.WindowsRuntime` DLL 其实已在进程里；改从 `AppDomain.CurrentDomain.GetAssemblies()` 按 `GetName().Name == "System.Runtime.WindowsRuntime"` 找程序集 → `asm.GetType("System.IO.WindowsRuntimeStreamExtensions", false)` → 反射取 1 参数 `AsStreamForRead` → `mi.Invoke(null, new object[]{ st })` 直接把原始 `__ComObject` 传进去（CLR 自动 COM 接口协商）→ `Stream.CopyTo(MemoryStream)` → base64。真实会话「一生不变（港风女版）」拿到 `bytes=46512 / magic=89504e470d0a1a0a / png=true`。**同进程即可，不需要 C# 原生辅助进程、不引用任何 `.winmd`**（绕开 CS1701/CS0012）。反证：`Assembly.Load("System.Runtime.WindowsRuntime")` 按简单名 `FileNotFoundException`、`Marshal.QueryInterface` 转 IID `905A0FE1-...` 仍 0 字节、强转 `IRandomAccessStream` 报转换失败。见 `docs/Spec/SPEC-music-cover.md` 第七节。
  - **同名变量陷阱（实现期实测踩过）**：`-File` 脚本主脚本体就是 script 作用域，`function GetCover` 里用 `$script:coverKey` 存缓存键、poll 分支里又用 `$coverKey` 算当前键，是同一个变量，算键先把缓存覆盖掉 ⇒ 首帧误判「未换歌」恒返回 `$null`。缓存键改名 `$script:coverCacheKey`、poll 算键用 `$coverId` 后，首帧拿到真实 PNG、第二次 poll 回 `null` 缓存生效。- **卸载 Radmin VPN 不删虚拟网卡/驱动/服务（2026-11-19 实测清理）**：软件目录、卸载注册表项、启动项都清掉后，`Get-NetAdapter` 仍有一块 `Radmin VPN`（Famatech Radmin VPN Ethernet Adapter，Virtual=True，Status=Up），`Get-NetConnectionProfile` 里也有一条 `NoTraffic` 的 `Radmin VPN`；驱动 `C:\Windows\System32\drivers\RvNetMP60.sys` 仍在、驱动服务 Running、驱动包 `oem106.inf`（netmp60.inf）；服务 `RvControlSvc` 仍注册且启动类型「自动」，指向已删除的 `C:\Program Files (x86)\Radmin VPN\RvControlSvc.exe`，每次开机启动失败。这正是断网时仍能读到「有一条网络连接」的原因。清法（管理员）：`pnputil /remove-device "ROOT\NET\0000"` → `pnputil /delete-driver oem106.inf /uninstall` → `sc.exe delete RvControlSvc` → 删 `HKLM\SYSTEM\CurrentControlSet\Services\RvNetMP60`（pnputil 留下 `Start=4` 的死键）。清完 `Get-NetAdapter`/连接配置只剩 WLAN，无需重装。产品侧仍保留「虚拟网卡不算真实连接」的判断作兜底。

### 测试与验证

- **SendKeys 模拟输入不可靠**：点击展开后焦点易丢失，按键进了别的窗口。自动化一律走 CDP。
- **e2e 不能用 skip 掩盖功能坏了（2026-11-11 独立验收发现）**：`scripts/e2e-music.mjs` 原来把「本机真没会话」和「有会话但读不到」混成一条 `skip()`，功能已坏仍报 PASS。凡是「环境不满足」的跳过，都要再用一条**独立**查询证明环境确实不满足（音乐页用一段单独的 PowerShell 数会话数，不复用被测链路），否则判失败。另外脚本必须以 `process.exit(failed > 0 ? 1 : 0)` 结束。
- **e2e 等应用就绪不要固定 sleep**：固定 `sleep(3500)` 在慢机上会让断言读到迁移前的 prefs。改成轮询 CDP 就绪（迁移在 `app.whenReady` 里、窗口创建前完成，看到 target 即代表迁移已落盘）。
- **重启后 React 首帧可能还没挂载**：`document.querySelector('.island')` 为 null，`el && el.click()` 会静默不点，后续读到 0。要写 `ensureExpanded()` 轮询到元素出现且 `expanded` 为止。
- **`--user-data-dir` 会覆盖 `app.getPath('userData')`（2026-11-20 实测）**：隔离实例里把 `APPDATA` 指到假目录后，userData 仍然跟着 `--user-data-dir` 走，`cleanup-backup`、`residue-backup` 这些目录都建在那个目录下。写测试夹具时要放到 `<user-data-dir>/` 里，放到 `%APPDATA%/<应用名>` 下应用读不到。
- **CDP 端口用 9321**（9222/9223/9230 会被残留实例或 DSH 宿主占用）。
- **打包版也能开 CDP（2026-11-20 订正）**：原记录「打包版无 CDP」不成立。给装机版 exe 加 `--remote-debugging-port=9333` 启动，`/json/list` 能拿到页面 target（title「灵动岛」，url 指向 `D:\软件\灵动岛

- **`.mjs` 里不能写 TS 注解**：e2e 脚本是纯 JS，`function f(): void` 直接 SyntaxError。复杂表达式别塞 `node -e`（引号地狱），一律写 `.mjs` 文件。

- **往 Windows 通知库投的 toast 删不掉（2026-11-12 实测）**：`ToastNotificationManager.History.Clear(appId)` 只清通知中心显示、`History.Remove(tag, group, appId)` 返回空且都不删 `wpndatabase.db` 的行。往库里投入的探针条目会永久留在岛的「通知」页。所以 e2e 注入种子 toast 必须 opt-in（`E2E_SEED_TOAST=1`），默认只读真实数据。
