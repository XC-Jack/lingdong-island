`package.json` 关键字段：`name: lingdong-island`、`main: ./out/main/index.js`、`build.appId: com.xcjack.lingdong-island`、`productName: 灵动岛`、`output: release`、`nsis.oneClick: false` / `allowToChangeInstallationDirectory: true`。

## 选型理由与被否方案

**选 Electron 理由**：界面表现力最好；Windows 上透明、穿透、置顶三项成熟度最高。React 界面代码将来可整块迁到 Tauri，不锁死。

| 被否方案 | 否决理由 |
|---|---|
| Tauri 2 | 内存更小，但 Windows 透明有边缘毛刺 |
| WPF / WinUI 3 | 界面代价过高 |
| C# + WebView2 混合 | 两边缺点都占 |

## 进程结构

```
src/
├── main/        主进程：窗口、系统能力（电量、通知库、图标、自启、提醒、全屏避让、偏好、导出、剪贴板）
│   ├── index.ts         窗口创建、尺寸动画、IPC 汇聚
│   ├── todoStore.ts     待办读写
│   ├── shelfStore.ts    置物架读写 + 图标提取
│   ├── scheduleStore.ts 日程读写 + 到点提醒
│   ├── notifyStore.ts   通知库读取
│   ├── statusStore.ts   电量读取
│   └── …（共 11 个模块，另有 fullscreenWatch / notifyIconStore / prefsStore / exportStore / clipboardStore，逐个作用见 README.md）
├── preload/     桥接层：contextBridge 暴露 window.island.*（含类型声明 index.d.ts）
├── renderer/    渲染层：React 单文件 App.tsx（实测 114250 字节）+ styles.css（实测 45707 字节，2026-11-08 核对）
└── shared/      两端共用的类型（types.ts）
```

上图的 main 模块清单只列早期 6 个，完整清单以 `README.md`「src 里每个文件是干什么的」为准；体积是 2026-11-08 实测值，早期的体积估算已作废。

**无数据库**：数据全部以 JSON 落在 `userData` 下，规则见 `docs/facts/数据规则.md`。

## 关键架构决策

1. **窗口尺寸自适应**：`.island` 用 `max-content` + min/max 夹逼；渲染层 ResizeObserver 监测内容尺寸，去抖 80ms 后通过 IPC 上报主进程，主进程 clamp（`EXPANDED_MIN 420×220` / `EXPANDED_MAX 720×420`）后调用 `animateTo`。
2. **不可全局给 `.page-fade` 设 `width:100%`**：日程页 `.sched-split` 依赖 `max-content` 撑开，与 `.island` 的 max-content 互锁，全局撑满会把日程页从 553 压到 420 并裁内容。只有第 2/3 页（置物架、通知）用 `.page-fade.wide`。
3. **弹出层统一模式**：state + absolute 浮层 + `document.mousedown` + `contains` 判断点外收起。已用于时间面板（`.sched-time-pop`）、视图菜单（`.shelf-view-pop`），新弹层直接复用。
4. **图标体系**：全部 SVG（`IconSvg` + 各 `Ico*` 组件，`stroke: currentColor`），不用 emoji——跨平台渲染一致、可随主题着色、缩放不糊。
5. **IPC 直调不刷新 UI**：见 `docs/facts/数据规则.md` 的「广播与刷新分离」。
6. **无原生 C++ 依赖**：本机没有 VS 原生工具链，任何需要 node-gyp 编译的依赖都不选。

## 系统能力接入方式

| 能力 | 方式 |
|---|---|
| 电量 | `spawnSync('powershell.exe', ['Get-CimInstance -ClassName Win32_Battery'])`，主进程 30s 缓存，渲染层 60s 轮询（`src/main/statusStore.ts`） |
| 通知历史 | 复制 `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db` + wal + shm，`node:sqlite` 只读打开，30s 轮询 |
| 系统图标 | 文件夹/真实路径走 `SHGetFileInfo`（PowerShell P/Invoke 脚本），结果 PNG 缓存 `userData\icon-cache\<ext>.png` |
| 开机自启 | `app.setLoginItemSettings({ openAtLogin, args })`，args 必须含 app 绝对路径 + `--hidden` |
| 文件路径 | preload 的 `webUtils.getPathForFile(file)`（Electron 32+ 没有 `File.path`） |
| 提醒 | `new Notification()`，主进程每 60s 扫描 `scheduleStore` |
| 音乐（SMTC） | 常驻 `powershell.exe` 子进程 + 行协议（`poll`/`toggle`/`next`/`prev`/`resync`），1s 轮询、变化才广播；脚本正文在 `src/main/smtcScript.ts`，落盘成 `userData\music\smtc-bridge.ps1`（**必须带 UTF-8 BOM**）。控制走 `TryTogglePlayPauseAsync`/`TrySkipNextAsync`/`TrySkipPreviousAsync` |

## 决策记录

> 一条事实一处维护。新决策追加在此，写明日期、结论、理由。

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-11-03 | 技术栈定为 Electron + React + TS + electron-vite | 四方案对比，用户批准 |
| 2026-11-03 | 不做鼠标穿透 | 整窗穿透会让胶囊点不开；窗口小、透明区仅四角，收益极小。将来精修用原生 `WS_EX_TRANSPARENT` 分区域 |
| 2026-11-03 | 窗口留缝隙 `TOP_GAP = 6px` | 用户未答，按此实现；一处常量可改 |
| 2026-11-04 | 日程与待办全部按「今天」处理，不加日期字段 | 先跑通体验，跨天需求将来再加字段并迁移 |
| 2026-11-04 | 移除验证码识别功能 | 用户的实际验证码从不经过电脑 |
| 2026-11-11 | 音乐信息与控制走 Windows SMTC（`GlobalSystemMediaTransportControlsSessionManager`），不接第三方音乐平台 API | SMTC 是系统级接口，任何注册它的播放器都能用，不依赖某家平台、不会被对方改接口破坏（这正是否决 US-031 的原理由，重启时已不成立） |
| 2026-11-11 | SMTC 桥接用「常驻 PowerShell 子进程 + 行协议」，不每秒 spawn | 实测单次 `powershell.exe` 启动约 755ms，每秒起进程明显卡顿；常驻后单次往返约 19ms |
| 2026-11-11 | 音乐页不做封面图（用音符占位） | PowerShell 5.1 无法把 SMTC 缩略图的 `System.__ComObject` 转成可读流，三条路（PS 直读 / `Add-Type` 编译 C# / 直接调 csc.exe）都实测失败；后续若要另开 SPEC 走独立 .NET 辅助进程 |
