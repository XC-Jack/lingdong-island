## 选型理由与被否方案

**选 Electron 理由**：界面表现力最好；Windows 上透明、穿透、置顶三项成熟度最高。React 界面代码将来可整块迁到 Tauri，不锁死。

| 被否方案 | 否决理由 |
|---|---|
| Tauri 2 | 内存更小，但 Windows 透明有边缘毛刺 |
| WPF / WinUI 3 | 界面代价过高 |
| C# + WebView2 混合 | 两边缺点都占 |

│   ├── scheduleStore.ts 日程读写 + 到点提醒
│   ├── notifyStore.ts   通知库读取
│   ├── statusStore.ts   电量读取
│   └── …（共 11 个模块，另有 fullscreenWatch / notifyIconStore / prefsStore / exportStore / clipboardStore，逐个作用见 README.md）
├── preload/     桥接层：contextBridge 暴露 window.island.*（含类型声明 index.d.ts）

上图的 main 模块清单只列早期 6 个，完整清单以 `README.md`「src 里每个文件是干什么的」为准；体积是 2026-11-08 实测值，早期的体积估算已作废。

**无数据库**：数据全部以 JSON 落在 `userData` 下，规则见 `docs/facts/数据规则.md`。

## 关键架构决策

1. **窗口尺寸自适应**：`.island` 用 `max-content` + min/max 夹逼；渲染层 ResizeObserver 监测内容尺寸，去抖 80ms 后通过 IPC 上报主进程，主进程 clamp（`EXPANDED_MIN 225×113` / `EXPANDED_MAX 540×315`，视觉 px）后调用 `animateTo`。数值由 CSS 布局 px 300~720 × 150~420 按 `zoom:0.75` 换算而来，改一边必须同步改另一边。
2. **不可全局给 `.page-fade` 设 `width:100%`**：日程页 `.sched-split` 依赖 `max-content` 撑开，与 `.island` 的 max-content 互锁，全局撑满会把日程页从 553 压到 420 并裁内容。只有第 2/3 页（置物架、通知）用 `.page-fade.wide`。
3. **弹出层统一模式**：state + absolute 浮层 + `document.mousedown` + `contains` 判断点外收起。已用于时间面板（`.sched-time-pop`）、视图菜单（`.shelf-view-pop`），新弹层直接复用。
4. **图标体系**：全部 SVG（`IconSvg` + 各 `Ico*` 组件，`stroke: currentColor`），不用 emoji——跨平台渲染一致、可随主题着色、缩放不糊。
5. **IPC 直调不刷新 UI**：见 `docs/facts/数据规则.md` 的「广播与刷新分离」。
6. **无原生 C++ 依赖**：本机没有 VS 原生工具链，任何需要 node-gyp 编译的依赖都不选。

## 系统能力接入方式

| 能力 | 方式 |
|---|---|
| 电量 | 异步 `spawn` 跑 PowerShell（`Get-CimInstance Win32_Battery` + `Get-NetConnectionProfile`），主进程 60 秒兜底缓存 + 事件驱动（powerMonitor 插拔电源/休眠恢复、Chromium online/offline、TCP 探针翻转），渲染层 60 秒兜底轮询（`src/main/statusStore.ts`）。**2026-11-22 前是 `spawnSync`、10 秒缓存 + 15 秒轮询**：一次读 830–925 ms 且整段阻塞主进程，而它挂在每次 pointerdown 上，是「点一下就卡」的根因（SPEC-perf-no-sync-ps）。 |
| 通知历史 | 复制 `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db` + wal + shm，`node:sqlite` 只读打开，30s 轮询 |
| 系统图标 | 文件夹/真实路径走 `SHGetFileInfo`（PowerShell P/Invoke 脚本），结果 PNG 缓存 `userData\icon-cache\<ext>.png`。**异步 + 串行**（同 key 单飞、不同 key 排队）：一次只跑一个 PowerShell，界面先出 SVG 占位再替换（SPEC-perf-no-sync-ps） |
| 开机自启 | `app.setLoginItemSettings({ openAtLogin, args })`，args 必须含 app 绝对路径 + `--hidden` |
| 文件路径 | preload 的 `webUtils.getPathForFile(file)`（Electron 32+ 没有 `File.path`） |
| 提醒 | `new Notification()`，主进程每 60s 扫描 `scheduleStore` |
| 音乐（SMTC） | 常驻 `powershell.exe` 子进程 + 行协议（纯文本 `poll`/`toggle`/`next`/`prev`/`resync` + 2026-11-15 起带参数命令用一行 JSON：`{"cmd":"seek"/"shuffle"/"repeat"/"volume","value":...}`），1s 轮询、变化才广播；脚本正文在 `src/main/smtcScript.ts`，落盘成 `userData\music\smtc-bridge.ps1`（**必须带 UTF-8 BOM**）。控制走 `TryTogglePlayPauseAsync`/`TrySkipNextAsync`/`TrySkipPreviousAsync`/`TryChangePlaybackPositionAsync`/`TryChangeShuffleActiveAsync`/`TryChangeAutoRepeatModeAsync`；音量走内嵌 C#（namespace `IslandAppVol`）枚举 Core Audio 音频会话、`IAudioSessionControl2.GetProcessId` 取 PID，与 SMTC `SourceAppUserModelId` 三层对号入座（精确名/AUMID → 扫进程窗口标题/产品名建候选 `ProcessName` 集合 → 全场唯一 active 会话），只读写匹配那条 `ISimpleAudioVolume`（**绝不碰系统主音量 `IAudioEndpointVolume`**；对不上号 `canVolume=false` 置灰）。**三次修订（用户 m01006 拍板）**：真实播放器「汽水音乐」无法通过 SMTC 真随机/循环、也读不到开关状态，随机/循环按钮、图标与「一按就变粉」的本地乐观假逻辑全部**删除**；桥接层 shuffle/repeat 字段与四条命令协议内部保留、UI 不暴露。音乐页最终控件＝上一首/播放暂停/下一首 + 进度条点播 + 按应用音量。**第 2 批（2026-11-15，分支 `music-cover`）**：封面走同进程反射 `System.IO.WindowsRuntimeStreamExtensions.AsStreamForRead` 读 `Thumbnail` 字节成 `data:image/png;base64,...`（内嵌 C# `IslandCoverGrab`），按 `app|title|artist|album` 缓存、未换歌回 `$null` 沿用缓存，取不到只回空串回落音符占位；详见 `docs/Spec/SPEC-music-cover.md` |
