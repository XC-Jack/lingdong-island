# 视觉设计规范（给 AI 看的 DESIGN.md）

这份文档是「灵动岛」的视觉规范，专门给 AI 看：以后新增界面、改界面、补组件时，AI 先读这份，按里面的规则做，不用每次重新猜。

来源说明：框架来自 VibeCoding UI 设计课视频里讲的「DESIGN.md 八板块」，视频网址对应的博主文章是 https://docs.starxops.com/articles/702c2907-62ef-4f68-84f4-024c4c6bc49c 。文中所有具体数值都取自本项目当前代码（`src/renderer/src/styles.css`、`src/main/index.ts`、`src/renderer/src/App.tsx`），[实测] 有出处，[推断] 标了理由，不是凭空写的。

## 整体气质

1. 定位：Windows 桌面顶部悬浮的胶囊「灵动岛」，深色、克制、信息密度高，不抢桌面主体。
2. 一句话风格：**三套主题共用一套语义 token**——默认 B 是**真透视乳白玻璃**（抓屏模糊的桌面底图 + 62% 乳白 veil，深字），A 是纯黑玻璃（白字），C 是纯黑极简（白字、无描边、实心块面）；共同的骨架是「单一强调色 + 同心圆角胶囊 + 靠明暗分层而不是描边分块」。
3. 情绪：工具感、利落、轻量，不用卡通、不用高饱和大面积色块。
4. 参考原点：先定「像什么」再动手——本项目像「桌面顶部的一颗深色信息胶囊」，不是网页、不是手机 App。
5. 图标：全部用 SVG，不用 emoji，不用外链图标。
6. 2026-11-24 起分两步换皮（SPEC-visual-refresh）：**第一步只换观感（颜色/字体/圆角/层次/字号），结构与交互一律不动**；组件化网格、统一面板尺寸放第二步。下面各项描述的是第一步完成后的现状。

## 色彩系统

**所有颜色走主题 token**（`styles.css` 文件头三段主题变量），新增界面不要再写裸色值，也不要新增第二套变量名。

主题由 `<html data-theme>` 决定（`App.tsx` 的 `applyIslandTheme()`）：缺省/`glass-light` = B 亮色乳白玻璃，`glass-dark` = A 纯黑玻璃，`mono` = C 纯黑极简；非法或缺失一律回落 B。偏好字段是 `prefs.islandTheme`（`src/shared/types.ts` 的 `ISLAND_THEMES`）。换肤入口在**设置 → 外观**（`ThemeSection.tsx`，2026-11-24）；设置窗口自己始终是深色，不参与换肤。

1. **中性层只由一个源色派生**：`--ink-1` 是主文字色，也是所有中性层的基色——`--ink-2..5`（文字档）、`--surface-1..3`（表面档）、`--line/-2/-3`（描边档）都用 `color-mix(in srgb, var(--ink-1) X%, transparent)`。所以「明暗翻转」只改一个变量，组件规则不动 [实测 `styles.css` 主题块]。
2. 三套主题的 `--ink-1`：B `#14161b`（深字）／A `#ffffff`／C `#f5f5f7`。三套的次要文字透明度档不同：B 82/62/52/26%，A 与 C 72/50/42/22%——43% 的黑压在乳白底上只有 2.6:1，浅底必须加重 [实测 计算值 + 截图核对]。
3. 岛体材质三套各自给：B 上 `rgba(247,243,244,.62)` 下 `rgba(233,218,211,.62)` + 三块低饱和色斑（左上受光/右上冷光/右下暖光）+ 深色投影；A 近纯黑两段（`rgba(10,10,12,.97)` → `rgba(5,5,7,.97)`）+ 11% 白描边 + 内高光；C 纯 `#000`、无描边、无投影 [实测 `styles.css` 主题块]。
   三块色斑 + 两段底色合成一个变量 `--island-veil`，`.island` 和真透视的 `.island-veil` 层共用它，改一处两边同时变。
4. **B 的真透视底图（2026-11-24 第二轮）**：`.island-backdrop`（抓来的桌面截图，`blur(22px) saturate(1.28)`）+ `.island-veil`（上面的 `--island-veil`），两层都在 `z-index:-1`，靠 `.island { isolation: isolate }` 落在岛体背景之上、内容之下。新增界面时**不要**给 `.island` 的直接子元素写 `z-index: 0` 或负值，也不要动 `.island` 的 `position/overflow`，否则底图会被盖住或跑出来。底图只在 `glass-light` 下存在（A/C 不透明，抓了也看不见）。
5. 强调色：B `#0a6cf0`（亮底上够深）；A/C 用主题文字色（白）当强调，配 `--accent-ink` 做反色文字。`--accent-soft` 是「同色调的更保险文字色」，B 由 accent 72% + ink 28% 得到深蓝，A/C 与 accent 相同。
6. 语义色三套各自加深/提亮：B 绿 `#12894a`、琥珀 `#9a5b00`、红 `#d92d20`；A/C 沿用亮色系 `#79d69b` / `#e9c46a` / `#f2758c`。实心语义底上的文字用 `--on-ok` / `--on-danger`，**不要**写 `var(--ink-1)`（浅主题下会变成黑字压深底）。
7. 音乐页的粉色属于这一页的专属强调，单独走 `--music-play / --music-play-hover / --music-play-ink`，不与危险红混用。
8. 用法：强调色只给「正在发生、需要注意、当前选中」的状态；语义色只在对应语义出现，不混用。新增颜色先问「它属于文字档、表面档、描边档还是语义色」，能派生就不要新值。

## 字体与排版

1. 字体栈 `--font-ui`：`'Segoe UI Variable Text', 'Segoe UI Variable Display', 'Noto Sans SC', 'Microsoft YaHei UI', system-ui, sans-serif` [实测 `styles.css:44-45`]。拉丁与数字走 Segoe UI Variable，中文走 Noto Sans SC（本机已安装）；不再用 Microsoft YaHei 打头。不引外部字体文件。
2. 字重三档：600 主操作 / 500 正文强调 / 400 正文；标题 700，不用 800（变体字体在 800 上会合成加粗）[实测 `styles.css` `.panel-title`、`.head-info .collapsed-clock`]。
3. 字号范围：全站 10–18px，常用主体 11.5/12/13/15px [实测 `styles.css` 多处 font-size；2026-11-24 把 9/10 两档各抬 0.5px]。
4. 大号：17.5px / 18px 用于标题或主数值；小号：10px / 10.5px 只用于角标、辅助说明。
5. 缩放：整个渲染层用 `zoom: 0.75` 统一缩放 [实测 `styles.css` `.app`]，写样式时按缩放后的视觉大小判断。
6. 排版原则：一行只说一件事；数字、单位、状态词优先，少写长句。中文标题可加 `letter-spacing: 0.01em`。

## 布局与响应式

1. 悬浮定位：窗口贴桌面顶部，`TOP_GAP = 6px` [实测 `src/main/index.ts:61`]。
2. 收起态：高 52px、圆角 26px、左右内边距 19px、图标间距 12px [实测 `styles.css:89-107`]；窗口高度常量 `COLLAPSED_WIN_HEIGHT = 76` [实测 `main/index.ts:37`]。
3. 展开态：逻辑窗口最小 255×113、最大 540×315 [实测 `main/index.ts:56-57`]。
4. 布局方式：React 组件 + 绝对定位浮层；弹出层统一用 state 控制，配 `document.mousedown` + `contains` 判断点外面关闭 [实测 `docs/facts/技术方案.md` 与 `App.tsx`]。
5. 尺寸原则：先保证收起态不挡视线，再让展开态内容从左到右、从上到下分组；超长内容滚动，不撑破窗口。
6. 响应式：这是固定桌面悬浮窗，不做手机端断点；不同系统字体差异靠字体栈兜底。

## 形状

1. 岛体圆角：收起态 26px（高 52px，正好半圆端 = 胶囊），展开态 24px（`--r-lg`）[实测 `styles.css:151,178`]。
2. 内容区圆角：16px / 14px / 12px / 10px / 9px / 8px / 7px / 6px / 4px，按层级递减 [实测 `styles.css` 多处 border-radius]。
3. 控件圆角：三档阶梯 `--r-sm` 10px（按钮、输入框、列表行、页头徽章）/ `--r-md` 16px（卡片）/ `--r-lg` 24px（岛体外框）；同心关系：24 的外框配 8px 内边距后内层约 16 [实测 `styles.css:38-40`]。
4. 胶囊标签：999px [实测 `styles.css` 多处]，只用于状态徽标、短标签、音源胶囊。
5. 圆形：50% 用于头像、圆点、圆形返回键。
6. 原则：外层更圆、内层更方；同类控件圆角一致，不混搭；新增元素优先用三档 token，不写字面量。

## 组件规范

1. 主要按钮：强调色实底 + 反色文字（`--accent` 底 / `--accent-ink` 字），圆角 10px；**一屏只允许一个实心强调按钮**，用来定位主操作 [实测 `.todo-add-btn`]。次要操作用 `--surface-*` 填充，不加描边。反色文字必须用 token：B 下是白字压蓝底，A/C 下是深字压白底。
2. 次要按钮：描边或淡底，视觉权重低于主按钮，避免两个按钮抢焦点 [推断 与视频「主要按钮/禁用状态/处理中」的状态区分思路一致]。
3. 禁用状态：降低不透明度、去掉交互反馈，让用户一眼看出不可用 [来源 视频 frame_017]。
4. 处理中状态：显示进度或 `role="progressbar"`，并阻止重复触发 [实测 `App.tsx` 有 role=progressbar]。
5. 输入框：包含只读字段（可查看可复制）、默认选项、错误输入、占位提示四类状态 [来源 视频 frame_017；项目沿用状态语义]。
6. 列表与菜单：用 `role="listbox"` / `role="menu"` 等语义标注 [实测 `App.tsx` 多处]。
7. 每个可点元素都要有 `aria-label` 或可读文字 [实测 `App.tsx` 大量 aria-label]，不用纯图标无标注。

## 组件首页（2026-11-24，SPEC-island-widget-grid）

1. 展开后第一层是组件网格：待办/置物架/通知/日程各一个 2×2 方格，音乐一条横跨两列的宽卡；顺序跟随「页面管理」（`enabledPages`）。
2. 卡片宽度：网格整体 308 布局 px（加左右内边距 16×2 后岛体仍是 340 最小宽），两列各约 149 布局 px，圆角 26（约为宽度的 17%，对齐 iOS 小组件）。
3. 卡面用 `--surface-1`，hover 用 `--surface-2`；图标是 28×28 的 9px 圆角小方块，底色为对应语义色 16% 透明度，图标本身用该语义色（待办 accent / 置物架 warn / 通知 danger / 日程 ok / 音乐 music-play），不新增裸色值。
4. 每张卡三行信息：图标、名称（13/600）、一句状态（10.5/500，`--ink-3`，单行省略）。待办卡右下角可带 26px 进度环。
5. 顶部一行：左侧「灵动岛」+ 日期，右侧沿用收起态那套状态组件（电量/时钟/网络/铃铛），整体 `scale(0.82)` 以适配网格宽度。
6. 交互：点卡片以 340ms FLIP 缩放放大成对应页面；功能页左上角 `.panel-back` 圆形返回键缩回网格。收起再展开总是回到网格。
7. 动画位移要按 `.app` 的 `zoom: 0.75` 折算：`getBoundingClientRect` 是屏幕坐标，`translate` 写的是元素布局坐标，差值要除以 0.75。

## 四页组件化（2026-11-24，SPEC-island-widget-pages）

1. 内容单元统一 16px 圆角（`--r-md`）：待办行、置物架列表行与文件格、通知行、月历整块。
2. 工具条按钮与时间按钮统一圆形；输入框统一 999px 胶囊（`.todo-input` / `.sched-input`）。
3. 空态（置物架、通知、音乐）统一为居中卡片：`color-mix(in srgb, var(--ink-1) 5%, transparent)` 底 + `--r-md` 圆角 + 18/24 内边距。
4. 大块面（月历）用 `color-mix(in srgb, var(--ink-1) 4%, transparent)` 而不是 `--surface-1`：`glass-dark` 没有单独定义 surface 档，会继承 `:root` 的 30% 白，在深色岛上会发亮。
5. 通知行的 `padding: 4px 8px` 与 31px 行高被 `e2e-notify-compact` 的 C1 精确断言，改视觉时不要动这两个值。
6. 音乐封面圆角 20（比卡片一档更圆），播放控件本就是圆形，进度条本就是胶囊。

## 页面导航（2026-11-24，SPEC-island-no-pager）

1. 功能页底部不再有翻页器（旧 `.pager` / `.pager-arrow` 已删）：页面入口只有组件网格，页内只有左上角返回键。
2. 页面之间切换 = 返回网格 → 点另一个组件；不再提供「上一页/下一页」横向翻页，因此原先圆点轮播的循环行为随翻页器一起下线。
3. `.dots-compat` 是 `display:none` 的测试兼容钩子，只给 e2e 程序化点 `.dots .dot` 用；它不是界面的一部分，不要再给它加可见样式。

## 日程页（2026-11-24，SPEC-schedule-day-popover）

1. 默认整页只有月历（宽 308，与组件网格一致），不再有右栏；点日期才弹当日安排浮层。
2. 浮层：绝对定位在月历中下部，`--bg-pop` 底 + 14 圆角 + `--shadow-pop`；关闭用 `visibility:hidden` + `pointer-events:none`，不占布局、不推高岛。
3. 浮层头部必须写清日期（浮层会盖住月历下半部），格式「M月D日 · N 条日程 · …」。
4. 浮层里的空态收小：隐藏图标，只留一行标题 + 一行提示。
5. 浮层里的时间选择面板向上展开：向下会越过 `EXPANDED_MAX.height = 315` 被窗口裁掉。
6. 浮层常驻 DOM 是测试兼容（旧 e2e 直接查 `.sched-input`），不是视觉规则；不要因为它在 DOM 里就当作可见元素去定位。

## 层次与深度

1. 层级**优先靠亮度**：岛体是底，卡片叠 `--surface-1`，控件叠 `--surface-2`，选中叠 `--surface-3`；描边用 `--line*` 只做边界提示，不靠一条条线切块。C 主题例外：它是实心块面，`--surface-*` 与 `--line*` 用固定深灰而不是透明度叠加 [实测 `styles.css` mono 块]。
2. `z-index` 分层：普通内容 1–2，弹出层 5–6，最外层提示 30 [实测 `styles.css:590,1153,1387,1419,1920,2509`]。
3. 浮层：绝对定位覆盖在岛体之上，带圆角和描边，不与底层内容混在一起。
4. 过渡：统一用 `cubic-bezier(0.22, 1, 0.36, 1)` [实测 `styles.css:51-59`]，展开/收起、浮层出现都沿用它，保持节奏一致。
5. 深度原则：越靠近用户当前操作的层，越亮、越清晰；背景层越淡。

## 设计约束

1. 目标：让操作和反馈都清晰 [来源 视频 frame_017]。
2. 键盘可用：打开弹窗后，用 Tab 切换焦点，用 Esc 关闭 [来源 视频 frame_017]。
3. Esc 约定：浮层、菜单、编辑状态都支持 Esc 退出；编辑框里 Esc 只取消编辑，不冒泡关掉整个岛 [实测 `App.tsx:609-610,659-660,1788-1789,2032,3530`]。
4. 点击外部：浮层用 `document.mousedown` + `contains` 判断是否点在外面，点外关闭 [实测 `docs/facts/技术方案.md`]。
5. 状态可见：按钮禁用、处理中、错误、成功都要有看得见的反馈，不只靠颜色区分，配文字或图标。
6. 约束优先于美观：与这些规则冲突时，先满足可用性和反馈清晰，再做视觉美化。

## 执行步骤（以后 AI 做新界面时照这个走）

1. 定方向：先说清楚这个界面「想像什么」，从现有风格里选一个参考，不先写代码。
2. 选组件：从本项目已有的按钮、输入框、列表、浮层里挑，不引入新组件库；需要新组件时说明理由。
3. 写规范：按本文件八个板块对照，新界面用到的新规则补进对应板块，再开始做；做完自检是否违反约束。
4. 自检：颜色有没有超范围、圆角是否同类一致、字号是否在 9–18px、键盘能否 Tab/Esc、状态反馈是否可见。
