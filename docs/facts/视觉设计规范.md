# 视觉设计规范（给 AI 看的 DESIGN.md）

这份文档是「灵动岛」的视觉规范，专门给 AI 看：以后新增界面、改界面、补组件时，AI 先读这份，按里面的规则做，不用每次重新猜。

来源说明：框架来自 VibeCoding UI 设计课视频里讲的「DESIGN.md 八板块」，视频网址对应的博主文章是 https://docs.starxops.com/articles/702c2907-62ef-4f68-84f4-024c4c6bc49c 。文中所有具体数值都取自本项目当前代码（`src/renderer/src/styles.css`、`src/main/index.ts`、`src/renderer/src/App.tsx`），[实测] 有出处，[推断] 标了理由，不是凭空写的。

## 整体气质

1. 定位：Windows 桌面顶部悬浮的胶囊「灵动岛」，深色、克制、信息密度高，不抢桌面主体。
2. 一句话风格：**四套主题共用一套语义 token**——默认 B 是**真透视乳白玻璃**（抓屏模糊的桌面底图 + 62% 乳白 veil，深字），A 是**真透视暗色玻璃**（同一套抓屏底图 + 半透明深色 veil + 冷/暖环境色斑 + 亮描边，白字，2026-11-25 重做），C 是纯黑极简（白字、无描边、实心块面），D 是**透明玻璃**（2026-11-25 新增：玻璃本体只有 5.5% 中性白、不压任何颜色、无外投影，白字）；共同的骨架是「单一强调色 + 同心圆角胶囊 + 靠明暗分层而不是描边分块」。
3. 情绪：工具感、利落、轻量，不用卡通、不用高饱和大面积色块。
4. 参考原点：先定「像什么」再动手——本项目像「桌面顶部的一颗深色信息胶囊」，不是网页、不是手机 App。
5. 图标：全部用 SVG，不用 emoji，不用外链图标。唯一例外是 D 主题（`glass-clear`）组件首页的 3D 贴纸——用的是内嵌在 `src/renderer/src/assets/stickers/` 的 Fluent Emoji 3D（Microsoft，MIT），`folder.svg` 自绘；其余界面仍全 SVG。
6. 2026-11-24 起分两步换皮（SPEC-visual-refresh）：**第一步只换观感（颜色/字体/圆角/层次/字号），结构与交互一律不动**；组件化网格、统一面板尺寸放第二步。下面各项描述的是第一步完成后的现状。

## 色彩系统

**所有颜色走主题 token**（`styles.css` 文件头三段主题变量），新增界面不要再写裸色值，也不要新增第二套变量名。

主题由 `<html data-theme>` 决定（`App.tsx` 的 `applyIslandTheme()`）：缺省/`glass-light` = B 亮色乳白玻璃，`glass-dark` = A 暗色玻璃（设置页显示名「暗色玻璃」，2026-11-25 前叫「纯黑玻璃」，同日重做为真透视半透明玻璃），`mono` = C 纯黑极简，`glass-clear` = D 透明玻璃；非法或缺失一律回落 B。B、A、D 走真透视抓屏，C 不抓屏。偏好字段是 `prefs.islandTheme`（`src/shared/types.ts` 的 `ISLAND_THEMES`）。换肤入口在**设置 → 外观**（`ThemeSection.tsx`，2026-11-24）；设置窗口自己始终是深色，不参与换肤。

1. **中性层只由一个源色派生**：`--ink-1` 是主文字色，也是所有中性层的基色——`--ink-2..5`（文字档）、`--surface-1..3`（表面档）、`--line/-2/-3`（描边档）都用 `color-mix(in srgb, var(--ink-1) X%, transparent)`。所以「明暗翻转」只改一个变量，组件规则不动 [实测 `styles.css` 主题块]。
2. 四套主题的 `--ink-1`：B `#14161b`（深字）／A `#ffffff`／C `#f5f5f7`／D `#ffffff`。次要文字透明度档：B 82/62/52/26%，A 与 C 72/50/42/22%，D 76/54/42/22%——43% 的黑压在乳白底上只有 2.6:1，浅底必须加重 [实测 计算值 + 截图核对]。
3. 岛体材质四套各自给：B 上 `rgba(247,243,244,.62)` 下 `rgba(233,218,211,.62)` + 两块低饱和色斑（右上冷光/右下暖光）；A 上 `rgba(15,17,23,.42→.84)` 下 `rgba(7,8,12,.50→.88)`（区间由 `--island-lit` 决定，见下条）+ 两道极淡冷/暖环境色斑（右上冷光/右下暖光）+ 26% 白描边；C 纯 `#000`、无描边；D 只叠 5.5% 中性白 + 16% 白描边，颜色全部来自底图。**四套都没有外投影、也没有顶部打光**：2026-11-25 用户先要求去掉岛下方阴影，再要求「把顶部的打光都不要了」，所以 `--shadow-island` 为 `none`（不再有 `inset 0 1px 0` 顶沿高光），B 的左上受光斑（`--island-hi`）、A 的顶部受光带与内高光、D 的顶部 14% 受光带一并删除；B 与 A 的右上冷光、右下暖光属于环境色，保留 [实测 `styles.css` 主题块]。
   A 的 `--surface-1..3` 与 `--line..3` 单独定义成 7%/12%/18% 与 10%/16%/24% 白：从 `:root` 继承的 30/44/62% 是给乳白玻璃的，压在深色玻璃上会把卡片整片冲白、白字读不清。
   **A 的亮度自适应（2026-11-25，参考 Apple 液态玻璃）**：渲染层把抓来的底图画到 8×8 canvas，取亮度 **75 分位**（半白半黑时平均值判不出问题），0.30 以下映射 0、0.75 以上映射 1，写成 `.island` 上的 `--island-lit`；CSS 用它放大 veil 的 alpha。`@property --island-lit` 注册成 `<number>` + 600ms 过渡，避免抓屏刷新时跳变。纯白背景（白色应用）会自动加深到深灰，保证白字可读。
   色斑 + 两段底色合成一个变量 `--island-veil`，`.island` 和真透视的 `.island-veil` 层共用它，改一处两边同时变。
4. **三套玻璃的真透视底图（2026-11-24 第二轮；2026-11-25 A 也接入）**：`.island-backdrop`（抓来的桌面截图，`blur(22px) saturate(1.28)`）+ `.island-veil`（上面的 `--island-veil`），两层都在 `z-index:-1`，靠 `.island { isolation: isolate }` 落在岛体背景之上、内容之下。新增界面时**不要**给 `.island` 的直接子元素写 `z-index: 0` 或负值，也不要动 `.island` 的 `position/overflow`，否则底图会被盖住或跑出来。底图在 `glass-light`、`glass-dark` 与 `glass-clear` 下都存在；`mono` 是实心块面，不抓屏（`App.tsx` 的抓屏循环按 `islandTheme === 'mono'` 停）。抓到底图时 `.island` 带 `has-backdrop` 类；拿不到时 A 走 `.island:not(.has-backdrop)` 兜底，退回接近实心的深色玻璃保证白字可读。
5. 强调色：B `#0a6cf0`（亮底上够深）；A/C 用主题文字色（白）当强调，配 `--accent-ink` 做反色文字；D 用浅蓝 `#5b9dff` + `--accent-ink: #06111f`。`--accent-soft` 是「同色调的更保险文字色」，B 由 accent 72% + ink 28% 得到深蓝，A/C 与 accent 相同。
6. 语义色四套各自加深/提亮：B 绿 `#12894a`、琥珀 `#9a5b00`、红 `#d92d20`；A/C 沿用亮色系 `#79d69b` / `#e9c46a` / `#f2758c`；D 用 `#6fdc9b` / `#ecc36b` / `#ff8fa3`。实心语义底上的文字用 `--on-ok` / `--on-danger`，**不要**写 `var(--ink-1)`（浅主题下会变成黑字压深底）。
7. 音乐页的粉色属于这一页的专属强调，单独走 `--music-play / --music-play-hover / --music-play-ink`，不与危险红混用。
8. 用法：强调色只给「正在发生、需要注意、当前选中」的状态；语义色只在对应语义出现，不混用。新增颜色先问「它属于文字档、表面档、描边档还是语义色」，能派生就不要新值。

## 字体与排版

1. 字体栈 `--font-ui`：`'Segoe UI Variable Text', 'Segoe UI Variable Display', 'Noto Sans SC', 'Microsoft YaHei UI', system-ui, sans-serif` [实测 `styles.css:44-45`]。拉丁与数字走 Segoe UI Variable，中文走 Noto Sans SC（本机已安装）；不再用 Microsoft YaHei 打头。B/A/C 不引外部字体文件；D 的 `--font-ui` 以 `Inter` 打头（内嵌 `assets/fonts/Inter-var-latin.woff2`，SIL OFL 1.1，可分发），中文仍落 Noto Sans SC。
2. 字重三档：600 主操作 / 500 正文强调 / 400 正文；标题 700，不用 800（变体字体在 800 上会合成加粗）[实测 `styles.css` `.panel-title`、`.head-info .collapsed-clock`]。
3. 字号范围：全站 10–18px，常用主体 11.5/12/13/15px [实测 `styles.css` 多处 font-size；2026-11-24 把 9/10 两档各抬 0.5px]。
4. 大号：17.5px / 18px 用于标题或主数值；小号：10px / 10.5px 只用于角标、辅助说明。
5. 缩放：整个渲染层用 `zoom: 0.75` 统一缩放 [实测 `styles.css` `.app`]，写样式时按缩放后的视觉大小判断。
6. 排版原则：一行只说一件事；数字、单位、状态词优先，少写长句。中文标题可加 `letter-spacing: 0.01em`。

## 布局与响应式

1. 悬浮定位：窗口贴桌面顶部，`TOP_GAP = 6px` [实测 `src/main/index.ts:61`]。
2. 收起态：高 52px、圆角 26px、左右内边距 19px、图标间距 12px [实测 `styles.css:89-107`]；窗口高度常量 `COLLAPSED_WIN_HEIGHT = 76` [实测 `main/index.ts:37`]。
3. 展开态：逻辑窗口最小 255×113、最大 540×315 [实测 `main/index.ts:56-57`]。
4. 布局方式：React 组件 + 绝对定位浮层；弹出层统一用 state 控制，配 `document.mousedown` + `contains` 判断点外面关闭 [实测 `docs/facts/技术方案.md` 与 `App.tsx`]。
5. 尺寸原则：先保证收起态不挡视线，再让展开态内容从左到右、从上到下分组；超长内容滚动，不撑破窗口。
6. 响应式：这是固定桌面悬浮窗，不做手机端断点；不同系统字体差异靠字体栈兜底。

## 形状

1. 岛体圆角：收起态 26px（高 52px，正好半圆端 = 胶囊），展开态 24px（`--r-lg`）[实测 `styles.css:151,178`]。
2. 内容区圆角：16px / 14px / 12px / 10px / 9px / 8px / 7px / 6px / 4px，按层级递减 [实测 `styles.css` 多处 border-radius]。
3. 控件圆角：三档阶梯 `--r-sm` 10px（按钮、输入框、列表行、页头徽章）/ `--r-md` 16px（卡片）/ `--r-lg` 24px（岛体外框）；同心关系：24 的外框配 8px 内边距后内层约 16 [实测 `styles.css:38-40`]。
4. 胶囊标签：999px [实测 `styles.css` 多处]，只用于状态徽标、短标签、音源胶囊。
5. 圆形：50% 用于头像、圆点、圆形返回键。
6. 原则：外层更圆、内层更方；同类控件圆角一致，不混搭；新增元素优先用三档 token，不写字面量。

## 组件规范

1. 主要按钮：强调色实底 + 反色文字（`--accent` 底 / `--accent-ink` 字），圆角 10px；**一屏只允许一个实心强调按钮**，用来定位主操作 [实测 `.todo-add-btn`]。次要操作用 `--surface-*` 填充，不加描边。反色文字必须用 token：B 下是白字压蓝底，A/C 下是深字压白底。
2. 次要按钮：描边或淡底，视觉权重低于主按钮，避免两个按钮抢焦点 [推断 与视频「主要按钮/禁用状态/处理中」的状态区分思路一致]。
3. 禁用状态：降低不透明度、去掉交互反馈，让用户一眼看出不可用 [来源 视频 frame_017]。
4. 处理中状态：显示进度或 `role="progressbar"`，并阻止重复触发 [实测 `App.tsx` 有 role=progressbar]。
5. 输入框：包含只读字段（可查看可复制）、默认选项、错误输入、占位提示四类状态 [来源 视频 frame_017；项目沿用状态语义]。
6. 列表与菜单：用 `role="listbox"` / `role="menu"` 等语义标注 [实测 `App.tsx` 多处]。
7. 每个可点元素都要有 `aria-label` 或可读文字 [实测 `App.tsx` 大量 aria-label]，不用纯图标无标注。

## 组件首页（2026-11-24，SPEC-island-widget-grid；2026-11-27 五卡等大 + 拖动换位）

1. 展开后第一层是组件网格：待办/置物架/通知/日程/音乐**五张等大的卡**，两列排布（2+2+1）；顺序跟随「页面管理」（`enabledPages`）。**音乐卡 2026-11-27 起不再横跨两列**（`SPEC-widget-drag`）：宽卡塞不进两列网格，用户把它拖到中间时会空出一格、后面的卡整体错位。
2. 卡片宽度：网格整体 308 布局 px（加左右内边距 16×2 后岛体仍是 340 最小宽），两列各约 149 布局 px，圆角 26（约为宽度的 17%，对齐 iOS 小组件）。实测五卡均 112×66 视觉 px（88 布局高）。
3. 卡面用 `--surface-1`，hover 用 `--surface-2`；图标是 28×28 的 9px 圆角小方块，底色为对应语义色 16% 透明度，图标本身用该语义色（待办 accent / 置物架 warn / 通知 danger / 日程 ok / 音乐 music-play），不新增裸色值。
4. 每张卡三行信息：图标、名称（13/600）、一句状态（10.5/500，`--ink-3`，单行省略）。待办卡右下角可带 26px 进度环。
5. 顶部一行：左侧「灵动岛」+ 日期，右侧沿用收起态那套状态组件（电量/时钟/网络/铃铛），整体 `scale(0.82)` 以适配网格宽度。
6. 交互：点卡片以 340ms FLIP 缩放放大成对应页面；功能页左上角 `.panel-back` 圆形返回键缩回网格。收起再展开总是回到网格。
7. 动画位移要按 `.app` 的 `zoom: 0.75` 折算：`getBoundingClientRect` 是屏幕坐标，`translate` 写的是元素布局坐标，差值要除以 0.75。
8. **拖动换位（2026-11-27，`SPEC-widget-drag`）**：按下卡片后**移动超过 6 屏幕 px 就起拖**，不需要先长按等待（`GRID_DRAG_SLOP = 6`）。被拖的卡浮起（放大 1.04 + 投影 + 不透明底 `--bg-pop`，避免半透明卡叠字），其余卡**实时滑开让位**（iOS 主屏做法，160ms 缓动），松手落到哪格就占哪格，顺序写 `prefs.json` 的 `pagesCustom.pages`，设置窗口同步。按下后不移动就松手（不论按多久）按点击处理，打开对应页面。
   拖动期间每帧直接写 `el.style.transform`，不经 React 状态；pointermove 用 `requestAnimationFrame` 合并，布局只在起拖时快照一次，所以拖动不触发重渲染、不做强制回流。Esc 取消拖动并吞掉紧随的 click（浏览器在松手后约 300ms 才合成 click，吞窗口取 500ms）。
9. 网格固定高度 362 布局 px（透明玻璃 386）：五卡等大后从「两行方格 + 一条矮宽卡」变成三行 88 高方格，实测网格内容 322 + 上下内边距 40 = 362。

## 四页组件化（2026-11-24，SPEC-island-widget-pages）

1. 内容单元统一 16px 圆角（`--r-md`）：待办行、置物架列表行与文件格、通知行、月历整块。
2. 工具条按钮与时间按钮统一圆形；输入框统一 999px 胶囊（`.todo-input` / `.sched-input`）。
3. 空态（置物架、通知、音乐）统一为居中卡片：`color-mix(in srgb, var(--ink-1) 5%, transparent)` 底 + `--r-md` 圆角 + 18/24 内边距。
4. 大块面（月历）用 `color-mix(in srgb, var(--ink-1) 4%, transparent)` 而不是 `--surface-1`：`glass-dark` 没有单独定义 surface 档，会继承 `:root` 的 30% 白，在深色岛上会发亮。
5. 通知行的 `padding: 4px 8px` 与 31px 行高被 `e2e-notify-compact` 的 C1 精确断言，改视觉时不要动这两个值。
6. 音乐封面圆角 20（比卡片一档更圆），播放控件本就是圆形，进度条本就是胶囊。

## 页面导航（2026-11-24，SPEC-island-no-pager）

1. 功能页底部不再有翻页器（旧 `.pager` / `.pager-arrow` 已删）：页面入口只有组件网格，页内只有左上角返回键。
2. 页面之间切换 = 返回网格 → 点另一个组件；不再提供「上一页/下一页」横向翻页，因此原先圆点轮播的循环行为随翻页器一起下线。
3. `.dots-compat` 是 `display:none` 的测试兼容钩子，只给 e2e 程序化点 `.dots .dot` 用；它不是界面的一部分，不要再给它加可见样式。

## 固定页面尺寸（2026-11-24，SPEC-fixed-page-size）

1. 用户原话：「这个代办页就做如图这么大，现在每个页面不要再做伸缩了，伸缩老是卡」；二选一时选了「每页各自固定」。展开态宽度统一 340 布局 px；高度按页固定，页内增减内容、开关浮层都不改窗口尺寸，只有切页时换一次。
2. 固定高度（布局 px）：组件网格 362（透明玻璃 386，2026-11-27 `SPEC-widget-drag` 五卡等大后由 330 抬到 362）、待办 310、置物架 251、通知 292、日程 339、音乐 292（有歌曲时）。
3. 实现锚点是岛根类名：`view-grid` / `page-0`…`page-4`（App.tsx 渲染时按 `view` 给出），对应 `.island.expanded.view-grid` 与 `.island.expanded.page-*`。
4. 内容超出固定高度时在页内滚动（待办列表 3 行、通知 3 条、置物架列表固定 93 高），不再把岛撑高。
5. 浮层一律在岛内展开：待办日期月历格子压到 18×18、间距 1px、从输入行下方往下展开（2026-11-25 改，见「待办页」一节）；时间浮层留在输入行下方，两列高 112。`popFit.ts` 与 `--pop-extra` 已删除，`padding-bottom` 恒为 20。
6. 例外：音乐页点「词」进入歌词模式时保留原并排布局，岛变大到约 535×358 布局 px；关歌词回到固定尺寸。
7. 历史：上一版是「置物架/通知用 min-height 锁空态页高」，已被本节取代。
8. 切页时岛的宽高不做 220ms 过渡（`nav-snap`，SPEC-nav-jank）：窗口是一次性 `setBounds` 跳变的，岛也必须同步跳变，否则收缩方向会被窗口裁、`pageReady` 还会量到过渡起点。返回网格前先按缓存把窗口扩好（网格 362 比多数页高）。新增页时若改了固定高度，要沿用这套「先扩窗再切页」的顺序，不要把过渡加回来。

## 置物架视图切换（2026-11-24，最终版）

1. 只有两种视图：**大图标**（`.shelf-drop.lg`，横向一排滚动）和**列表**（`.shelf-drop.list`，纵向滚动）。中图标/小图标已按用户要求移除，相关样式与图标组件一并删除。
2. 工具条右侧是一个切换按钮 `.shelf-view-btn`，点一下在大图标 ⇄ 列表之间直接切换，**不弹菜单**（用户原话「就保留大图标和列表就行了，另外两个不要了，点切换键来切换」）。
3. 按钮显示当前视图的图标；`title`/`aria-label` 写的是「切换为列表」/「切换为大图标」，让用户知道点下去会变成什么。
4. **两种视图同尺寸**（用户 2026-11-24：「保持大图标的大小，不要变大变小了，界面老卡」）：`.shelf-grid` 与 `.shelf-drop.list .shelf-list` 都固定 `height: 93px`（=大图标网格布局高度，实测屏高 70 ÷ 0.75）。行数少时列表留白，多了在框内滚动。切换视图不再改变岛高，避免每次切换都重设窗口造成卡顿。
5. 空态（没有文件）两种视图内容相同，尺寸也一致。
6. 历史记录：这轮先试过四项下拉菜单（竖排撑高岛 → 横排不撑高），均被用户否掉；最终方案是删掉菜单、「中/小图标」和对应 CSS/组件，旧偏好 `md`/`sm` 由 `normalizeShelfView` 回落为「大图标」。

## 日程页（2026-11-24，SPEC-schedule-day-popover / SPEC-todo-day-add）

1. 默认整页只有月历（宽 308，与组件网格一致），不再有右栏；点日期才弹当日安排浮层。
2. 浮层：绝对定位贴在月历顶部并铺到月历底部（`top:38px` / `bottom:6px`），`--bg-pop` 底 + 14 圆角 + `--shadow-pop`；关闭用 `visibility:hidden` + `pointer-events:none`，不占布局、不推高岛。
3. 当天视图整块占满月历区域（用户 2026-11-24：「向下铺开，只有一半太丑了」）：内容少时留白，多时列表在浮层内滚动；高度锁在月历内，岛尺寸不变。
4. 浮层头部必须写清日期（浮层会盖住月历上半部），格式「M月D日 · N 条日程 · …」。
5. **日程页只看不添**（2026-11-24 用户要求）：浮层里没有输入框、时间按钮、加号；添加统一在待办页完成，空态提示写「在「待办」里选日期添加」。

## 待办页（2026-11-24，SPEC-todo-day-add）

1. 输入行顺序：输入框 → 日期按钮 → 时间按钮 → 加号。日期按钮默认写「今天」，选中非今天时写「M月D日」并亮强调色边框。

## 开合动画（2026-11-25，SPEC-island-motion；2026-11-26 修订，SPEC-expand-clip）

1. 打开/收起 = 主进程窗口补间 220ms（easeOutCubic、单调不过冲）+ 岛自身 `island-open` / `island-close` 关键帧（≤1 的缩放 + 淡入）。原 500ms 的「先冲过头再缩回」已按用户「震动动画容易卡」的意见改掉。
2. 渲染层必须在 `set-expanded` **之前**上报展开后的目标尺寸（临时关掉 `.island` 的宽高过渡再量），否则窗口会先按旧值开、再纠正。
3. 入场动画期间 `transform` 会让 `getBoundingClientRect` 偏小：ResizeObserver 在这段时间不上报，动画结束后补一次真实尺寸（`reportCurrentSize`）。新增尺寸上报逻辑时不要绕过这条。
4. 不要为了「更顺滑」把开合改成一次 `setBounds` 跳变：实测透明置顶窗跳变后合成器会有约 0.7–1.2s 不呈现新画面，屏幕是空的。
5. **展开入场期间，岛的宽高必须跟着窗口的实际尺寸走，不能按固定时长自己跑**（2026-11-26 用户视频实拍：展开瞬间岛被裁成页头一条「宽扁带」）。做法：App 每帧读 `innerWidth/innerHeight`，在「收起外框 → 面板外框」之间取进度，写入 `--entrance-w/h`（样式见 `.island.expanded.island-entrance`，布局 px 要除以 zoom 0.75）。这样窗口停住岛也停住，任何一帧岛都不会超出窗口。不要改回「CSS 过渡按固定时长跑」——主进程补间一旦被卡（抓屏就会卡 135~192ms），过渡照走而窗口不动，又会裁。
6. `island:backdrop` 在补间进行中（`tweenTimer` 非空）直接返回 `null`：`desktopCapturer.getSources` 实测阻塞主进程 135~192ms，会把 16ms 的补间定时器卡出 100ms 级空档。

## 层次与深度

1. 层级**优先靠亮度**：岛体是底，卡片叠 `--surface-1`，控件叠 `--surface-2`，选中叠 `--surface-3`；描边用 `--line*` 只做边界提示，不靠一条条线切块。C 主题例外：它是实心块面，`--surface-*` 与 `--line*` 用固定深灰而不是透明度叠加 [实测 `styles.css` mono 块]。
2. `z-index` 分层：普通内容 1–2，弹出层 5–6，最外层提示 30 [实测 `styles.css:590,1153,1387,1419,1920,2509`]。
3. 浮层：绝对定位覆盖在岛体之上，带圆角和描边，不与底层内容混在一起。
4. 过渡：统一用 `cubic-bezier(0.22, 1, 0.36, 1)` [实测 `styles.css:51-59`]，展开/收起、浮层出现都沿用它，保持节奏一致。
5. 深度原则：越靠近用户当前操作的层，越亮、越清晰；背景层越淡。

## 设计约束

1. 目标：让操作和反馈都清晰 [来源 视频 frame_017]。
2. 键盘可用：打开弹窗后，用 Tab 切换焦点，用 Esc 关闭 [来源 视频 frame_017]。
3. Esc 约定：浮层、菜单、编辑状态都支持 Esc 退出；编辑框里 Esc 只取消编辑，不冒泡关掉整个岛 [实测 `App.tsx:609-610,659-660,1788-1789,2032,3530`]。
4. 点击外部：浮层用 `document.mousedown` + `contains` 判断是否点在外面，点外关闭 [实测 `docs/facts/技术方案.md`]。
5. 状态可见：按钮禁用、处理中、错误、成功都要有看得见的反馈，不只靠颜色区分，配文字或图标。
6. 约束优先于美观：与这些规则冲突时，先满足可用性和反馈清晰，再做视觉美化。

## 执行步骤（以后 AI 做新界面时照这个走）

1. 定方向：先说清楚这个界面「想像什么」，从现有风格里选一个参考，不先写代码。
2. 选组件：从本项目已有的按钮、输入框、列表、浮层里挑，不引入新组件库；需要新组件时说明理由。
3. 写规范：按本文件八个板块对照，新界面用到的新规则补进对应板块，再开始做；做完自检是否违反约束。
4. 自检：颜色有没有超范围、圆角是否同类一致、字号是否在 9–18px、键盘能否 Tab/Esc、状态反馈是否可见。
