# 数据规则

> 本文件负责唯一事实：产品数据存在哪、存什么、怎么读写、什么不会丢。
> 结论均来自源码核对（路径 + 行号见各条），不是推测。

## 存储位置

全部数据落在 Electron 的 `app.getPath('userData')` 目录下，**不用数据库**，各模块一个 JSON 文件。

Windows 上实际路径形如：`C:\Users\<用户名>\AppData\Roaming\lingdong-island\`

| 文件 / 目录 | 内容 | 源码位置 |
|---|---|---|
| `todos.json` | 待办清单 | `src/main/todoStore.ts:37` |
| `shelf.json` | 置物架条目 | `src/main/shelfStore.ts:156` |
| `icon-cache/` | 系统图标 PNG 缓存 + 提取脚本 | `src/main/shelfStore.ts:157` |
| `schedule.json` | 日程条目 + 提醒状态 | `src/main/scheduleStore.ts:28` |
| `notif-read.json` | 通知已读 + 清空水位 `{lastOrder, hiddenUntil}`（旧文件只有 lastOrder，兼容） | `src/main/notifyStore.ts:120` |

四个 store 在初始化时都会 `mkdirSync(userData, { recursive: true })`（`todoStore.ts:38`、`scheduleStore.ts:41`、`notifyStore.ts:134`、`shelfStore.ts:158`），首次运行自动建目录。

## 读写约定

1. **写入时机**：渲染层每次操作（增/删/改/勾选/换位）都通过 IPC 通知主进程，主进程写盘后返回新列表，渲染层以返回值为准。
2. **广播与刷新分离**：`window.island.xxxAdd()` 这类 IPC 直调**只写盘不改 React state**。UI 刷新靠广播回调（如 `emitShelfAdded(list)` → `onShelfAdded` 订阅）。这是既有设计，不是 bug——但意味着 CDP 探针直调 IPC 看不到界面变化，验证界面必须走真实交互或补一次广播。
3. **顺序保护**：置物架换位用模块级 `reorderSeq` 递增序号，只采纳最新的响应，防止 IPC 慢响应乱序覆盖。
4. **只读外部数据**：通知数据复制三件套（db + wal + shm）后用 `node:sqlite` 只读打开，**不回写**系统通知库。通知「清空」也是本地操作：把 `notif-read.json` 的 `hiddenUntil` 水位提到当前最大 Order，`order<=hiddenUntil` 的通知从此不再显示（系统库里的原条目不动，所以 30 秒轮询拉回也不会重现）；新通知（order>水位）照常显示。
5. **界面偏好存渲染层**：置物架视图选择存在渲染层 `localStorage`（键 `island.shelfView`，实际文件在 `%APPDATA%\lingdong-island\Local Storage\`），**不新建 JSON、不新增 IPC**。读取时白名单校验 `lg` / `md` / `sm` / `list`，不认识的值回落 `lg`；读写都包 try/catch，存不了也不报错。
6. **退出前停轮询**：`quitApp()` 先 `stopNotifyStore()`（停 30 秒通知轮询）与 `stopScheduleStore()`（停 60 秒提醒检查）再 `app.quit()`。退出入口有两处：岛内右键菜单与托盘菜单。

## 数据规则

- **去重**：置物架按真实路径去重，同一个文件拖两次只保留一条。
- **相对路径**：置物架存的是**文件真实绝对路径**（通过 `webUtils.getPathForFile` 拿，Electron 32+ 没有 `File.path`），所以文件被移动/删除后会失效。
- **失效状态不落盘**：`ShelfItem.missing` 是主进程每次返回列表时用 `existsSync(path)` 现算的运行时字段（`src/main/shelfStore.ts` 的 `withMissing()`），**不写进 `shelf.json`**。好处是不需要迁移、文件放回原位后标识自动消失；代价是只在列列表时检查，文件在页面停留期间被删要等下次刷新才反映出来。
- **日程有日期**：`ScheduleItem.day` 是 `'YYYY-MM-DD'` 本地日期字符串（`src/main/scheduleStore.ts` 的 `dayKey()` 用本地时间拼，**不能用 `toISOString`**，那是 UTC 会差一天）。新增日程时若没传 `day` 或格式不合法，落到当天。
- **旧数据迁移**：`schedule.json` 里缺 `day` 或格式不合法的条目，启动时迁到「迁移当天」，迁移前把原文件整份备份成 `schedule.json.bak-<YYYYMMDD-HHmmss>`。迁移幂等：已是新格式就不再备份、不再改写。
- **待办仍不分日期**：待办没有日期字段，只在日程页选中「今天」时才与日程混排，选别的日子不显示待办（副标题写「待办只在今天」）。
- **待办页新增的是日程不是待办**：待办页（page 0）的输入框提交时调的是 `schedule:add` 并传本地今天的 `day`，所以新条目落在 `schedule.json`，`todos.json` 不会被写入。时间可选（`HH:mm` 或 null）。这一页只读取并显示 `day === 今天` 的日程，明天/昨天的一律过滤掉。
- **统计口径统一含今天日程**：展开态头部完成度（`todoStats`）与收起态数字都由「全部待办 + 今天的日程」算出，两处用同一个函数 `localDayKey()` 取日期，避免跨页数字不一致。
- **提醒只对当天**：`remindDue()` 跳过 `day !== 今天` 的条目，到点才弹，`reminded` 落盘防重复。
- **提醒状态**：日程的 `reminded` 标记落盘，重启后不会重复提醒同一条。
- **编辑日程**：`schedule:edit`（`src/main/scheduleStore.ts`）按字段更新：`text` 非空 trim 才改（空串视为取消，不清空原文）；`time` 走与新增相同的 `HH:mm` 规范化；`day` 走 `DAY_RE` 校验。**改 `time` 或 `day` 时该条 `reminded` 重置为 false**（时间变了旧提醒不算数）；只改文字不动 `reminded`，避免重复弹提醒。改名不影响其他字段。
- **过期判定**：未完成且（`day` 早于今天，或 `day` 是今天且 `time <= 当前 HH:mm`）→ 橙色标记；无时间但已过期的条目显示「逾期」。

## 备份与导出

- **US-029 数据导出（2026-11-06 实现，分支 `us-029-data-export`）**：右键/托盘菜单「导出数据…」→ 原生另存为对话框（默认文件名 `灵动岛备份-YYYYMMDD-HHmmss.json`，默认目录「文档」）→ 写 JSON：`{app:'lingdong-island', version:1, exportedAt:<本地时区 ISO>, todos:[...], schedule:[...]}`。待办与日程导出，**通知与置物架不导出**（通知是只读外部库 `wpndatabase.db`，置物架存的是本机绝对路径，换机器无意义）。导入功能未实现（见 SPEC 的「不做什么」）。实现：`src/main/exportStore.ts`，IPC `app:export-data`，入口在 `buildAppMenu()`。

| 场景 | 结果 |
|---|---|
| 卸载程序 | **不删数据**（userData 目录保留） |
| 清空置物架 | 只删 `shelf.json` 里的条目，**不删原文件** |
| 删除待办 / 日程 | 只删 JSON 里的条目 |
| 换机器 / 重装系统 | 数据不迁移会丢，但可先在旧机器上用「导出数据…」生成 JSON 备份带走（导入功能尚未实现，2026-11-06） |

## 数据相关的不可逆操作

- **卸载永远不会删 userData**（2026-11-05 重新实测确认）。本项目卸载器没有「同时删除应用数据」这个勾选项——electron-builder 只有在 one-click 安装模式并设置 `deleteAppDataOnUninstall` 时才会生成它，本项目两者都不满足。卸载页只是用中文告知「只删程序、数据在 `%APPDATA%\lingdong-island`、重装会自动读回」（`build/installer.nsh`）。
- 真要丢全部数据，只能由用户手动删除 `%APPDATA%\lingdong-island` 文件夹。
- 清空置物架有二次确认（第一次点变红底「确认清空？」），但删单条待办/日程没有二次确认，靠 Git 无法恢复用户数据（数据不在仓库里）。
