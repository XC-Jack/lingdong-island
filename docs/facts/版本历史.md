## 版本编号约定

- 标签名 = 里程碑编号、`polish-<主题>-<日期>` 或 `prod-<日期>`。
- 一个大改进如果用户已经体验过、且值得整体回退，就补打标签；纯修 bug 不单独打。
- `prod-<日期>` 是**生产版本锚点**：装机版验收通过后即时给当前 `main` 的 HEAD 补打，作为「下一轮从哪拉分支、要回退回哪一版」的固定起点。不必等大改进、不要求每个功能都打，但不能让锚点长期停在几百个提交之前——2026-11-08 补打 `prod-20261108`，就是因为此前最新标签 `polish-video-20261104` 已落后 198 个提交。标签名用装机当天的日期，与实际打标签的时刻（次日凌晨）可能差一天。
- 应用版本号（`package.json` 的 `version`）：2026-11-17 起按发版节奏递增（当前 `0.3.0`，Release 为 Latest）。每次对外发 Release 时同步升 `version`、打同名标签 `v<版本号>`，安装包文件名随之带上版本号。只在本地修 bug、不对外发版时不升版本号。**2026-11-19 起三段含义固定**：`X` 大改（0.x 阶段保持 0）、`Y` 加功能/改交互、`Z` 修 bug，细则见 `docs/工程规则.md` 第五节第 5 条。
- **发布资产三件套（2026-11-18 起）**：带自动更新之后，每个 Release 必须同时上传 `Lingdong-Island-Setup-<版本>.exe`、同名 `.blockmap`、`latest.yml` 三个资产，且最新一版不能标 Pre-release，否则 `electron-updater` 检查不到或下载失败。旧版按惯例标 Pre-release 并在说明开头加「旧版本」提示。安装包文件名由 `build.artifactName` 统一为 ASCII（中文名与 `latest.yml` 里的 url 对不上会导致 404）。
