## 逐项说明

### 0. 整体尺寸与观感

- **岛整体按 0.75 等比缩小（SPEC-island-compact，2026-11-11）**：用户原话「各个界面整体比例小一点，迷你一点，就是我没见过就是灵动岛这么大的」。实现方式是 `styles.css` 里 `.app { zoom: 0.75 }` 一处生效，字号、图标、内边距、圆角全部跟着缩，不是只缩外框；主进程的窗口尺寸上下限同步按 0.75 收缩（收起态窗口高 66、展开态上限 540×315）。**实测**：收起态胶囊 142×31.5（原 42 高）、窗口 144×67。
- **各页尺寸随内容自适应、带上下限（2026-11-16，用户 m00791/m00795 推翻 2026-11-11 的固定尺寸）**：`.island.expanded` 从固定 `470×320` 布局 px 改回 `width/height:max-content` + `min/max` 夹逼（布局 300~720 × 150~420 = 视觉 225~540 × 113~315，与主进程 `EXPANDED_MIN`/`EXPANDED_MAX` 一一对应）。内容少时岛收小（待办 0 条 225×158，不再是下方一块黑），内容多时岛长高到上限为止，超出部分在列表内部滚动、滚轮可查。列表统一「默认只显示 3 条」：`.todo-list` `max-height:114px`、`.notify-list` `136px`、`.shelf-drop.list .shelf-list` `130px`。实测各页宽高不再恒等：待办 225 / 通知 307 / 日程 393 / 置物架 225 / 音乐 225。历史：2026-11-11 第二轮曾把 `.island.expanded` 改成固定 440×252 布局 px（后调到 470×320，0.75 缩放后视觉 353×240），五个页面同尺寸、内容超出只在列表内部滚动；那条要求在 2026-11-16 被用户明确推翻。
- **翻页循环，第一页能跳最后一页（2026-11-11 第二轮 + 22:43 用户澄清）**：5 个圆点循环翻，「‹」在第一页会到最后一页、「›」在最后一页会回第一页。**原先报的「一直重复」是 bug 不是循环本身**：删页面管理后残留 `if (p === 4) return list[0]`——page 4 当年是页面管理面板，搬进设置窗口后 4 变成音乐页，于是翻到音乐页就被弹回第一页。该守卫和另一个 useEffect 里的 `if (p >= 4) return p` 豁免都已清掉，循环保留。
- **两个必须记住的实现坑**：①`zoom` 不能挂 `html`（会连视口 CSS 宽度一起缩，岛比视口宽 → 横向被裁），必须挂 `.app`；②`.app` 里不能写 `width: calc(100% / 0.75)`（`zoom` 元素的百分比已按缩放坐标系解析过，再除会宽一倍、岛跑到窗口右边被裁），写 `100%` 正好。

### 1. 待办清单（page 0）

- 这一页的定位是「今天要做什么」的速览：列表 = 所有待办 + **今天**的日程混排。明天的、昨天的日程都不出现在这里（要看别的日期去日程页）。
- 增加、勾选完成、删除、双击行内改名（空文本取消改名）。
- 完成度大号显示 `已完成数/总数`（如 `2/3`），这个总数把待办和今天的日程一起算。
- **完成度圆环 + 进度条（美化-04，2026-11-11）**：右上角那行数字左边加了一个 14px 的小圆环（底环 + 按完成比例顺时针填充的前景环，全做完时变实心绿带光晕），数字格式仍是 `n/m` 不变（两条 e2e 对它做精确字符串比对）；列表最下方多了一条横向进度条（细轨 + 圆头绿色填充 + 右侧「还差 N 件 + 百分比」，全做完时文案改「今天全部做完」）。两者都由同一份 `done/total` 驱动：圆环靠 SVG `stroke-dashoffset`、进度条靠 `transform: scaleX`，都用 320ms 缓动，切页时不跳。
- 勾选时 ✓ 有 `check-pop` 弹跳动画（180ms），触发岛仔开心。
- 加完一条后输入框保持焦点，可连续录入。
- 列表没有条数上限；内容超过岛高度上限后列表在岛内滚动（不显示滚动条），新加的一条会自动滚到底部进入视野（2026-11-05 修复，此前超长部分会溢出窗口被裁掉、看起来像「加不上」）。**2026-11-11 起岛高固定为 440×252 布局 px（视觉 353×240），不再按内容撑开**，所以条数一多就只在列表内滚。
- 在这一页加的内容存为**今天的日程**（不是待办）：今天在待办页和日程页都能看到，明天从待办页消失、仍留在日程页今天那一格。加的时候可以点右边的钟选一个时间，也可以不选。
- 列表里的日程条目：有时间的左侧显示 `09:00` 这样的时间徽标（只显示几点几分，不显示日期），过点还没完成的徽标变橙；可以直接勾选，勾选结果与日程页同步。
- 列表里的待办条目：与以前一样，没有时间徽标，双击可改名。
- 收起态就能看今天还剩几件：矮条最右侧（电量环右边、未读红点左边）只显示一个绿色数字 N（N = 待办 + 今天的日程里未完成的件数），不带图标。鼠标悬停提示「今天还有 N 件没做完（共 M 件）」。全部做完或一条都没有时这块不显示，不占地方。数字在「首次启动」和「每次从展开态收回」时各现算一次（不轮询），所以勾完一条收回就能看到数字减一。

### 2. 置物架（page 1）

- 拖入文件即暂存（整岛接收拖放），自动去重，持久化。
- 四种视图：大图标 84px / 中图标 64px / 小图标 48px / 列表；点击工具条按钮弹出菜单选择（不是循环切换）。
- 视图选择会记住（US-037 起）：选完写进主进程 `prefs.json` 的 `shelfView` 字段（经 `prefs:get`/`prefs:set` IPC），重启应用后仍是上次那个视图；从来没选过、或者值被改坏，都回落「大图标」，不报错。早期版本存渲染层 localStorage，跨重启会丢（见 US-037）。
- 图标视图横向胶片条，**一屏最多显示 4 个**（2026-11-16，用户 m01366「显示太多了，4个最多」）：`.shelf-strip` 的 `max-width` 按「正好放下 4 格」算（大图标 380 / 中图标 300 / 小图标 236 布局 px），`.shelf-cell` 加 `flex:none` 防止被压扁导致一屏塞进更多。放不下时两侧出现 `‹ ›` 滚动箭头，**到两端再点就绕回另一头（首尾循环）**；**滚轮也能横向滚**（竖向 `deltaY` 转横向 `scrollLeft`，两端同样绕回），见 SPEC-shelf-4up。列表视图上下滚动（隐藏滚动条），仍是默认 3 行。
- 架内图标拖动 = 互换位置（拖 A 到 B 上两格互换），带 `reorderSeq` 防乱序。
- 双击打开文件；每个格子有「在文件夹中显示」按钮。
- 原文件被移走/删除后，条目仍留在架子上但会标为**失效**：格子置灰、文件名带删除线、显示「失效」小徽标，鼠标悬停提示「文件已不在：<原路径>」。点它会弹出中文说明「「文件名」已经不在了，可能被移走或删除。」并给一个「从架子上移除」按钮；失效条目的「在文件夹中显示」置灰不可点。失效状态是打开页面时按文件系统实时算出来的，不写进 `shelf.json`，文件放回原处后会自动恢复。
- 清空按钮带二次确认（第一次点变「确认清空？」，红底）。
- 系统原生图标：文件夹走 `SHGetFileInfo` 提真实图标，普通文件按扩展名缓存。

### 3. 通知（page 2）

- 读 Windows 通知中心历史库，定时轮询，解析标题/正文/来源应用。
- 相对时间显示（刚刚 / x分钟前 / …），每 30s 重算；加载时显示骨架条。
- **未读蓝点（美化-04，2026-11-11）**：未读条目（`order` 大于已读水位 `lastOrder`）在条目**最右端**显示一个 6px 蓝点（相对时间右边），扫一眼就能看出哪几条没读；点「已读」后蓝点当场消失（`markRead` 会重新拉一次列表拿新水位，只改状态消不掉）。`lastOrder` 是 `notify:list`/`notify:refresh`/`notify:clear-all` 新暴露的字段，判定逻辑与未读红点同源。**当天实机试过后去掉了原来的「打开」按钮**（用户反馈「点了没什么效果」）；要打开就点开应用组后的具体条目正文，正文本身就是「打开来源应用」。
- 点通知打开来源应用（映射不到的兜底打开 Windows 通知设置，自家通知聚焦灵动岛窗口）；「已读」按钮全部标记；「清空」按钮本地隐藏列表（按 order 水位过滤，旧通知不再重现，新通知照常）；收起态显示未读红点。
- **通知页宽度收窄（SPEC-notify-width，2026-11-16，用户 m02896「这个通知消息的也改一下，宽幅有点长」）**：超长通知标题会把整页撑到岛宽上限 540 视觉 px。改法两层：`.notify-list` 加固定上限 `max-width:300px`（布局 px，视觉 225；**不用百分比**——百分比在宽岛上等于没限制，音乐页已踩过）；「（等 N 条）」是 `.notify-title` 的子元素，行内排布会被超长标题推出岛外，故 `.notify-title` 改 flex、标题文本包进 `.notify-title-text` 承担省略号、提示 `flex:none`。实测岛宽 406.2→**285** 视觉 px（与待办/置物架/音乐一致），提示完整显示。
- **组条目（主干）整理（SPEC-notify-group-tidy，2026-11-16，用户 m03042）**：展开某个应用组后 `.notify-item` 没换行，`.notify-sublist` 与主干并排横挤，把 `.notify-body` 压成 0 宽（标题看不见、时间叠在图标上）。改法：`.notify-group` 加 `flex-wrap:wrap; row-gap:3px`；`.notify-sublist` 的 margin 收到 `0 0 0 8px`、宽度 `calc(100% - 8px)`、`flex:0 0 auto`；主干**不再显示相对时间**（`renderSide(..., showTime=false)`，只留未读蓝点；组内每条自己带时间）。实测主干标题恢复 201.8 宽、分支独占下一行、组高 68.3→62.3。
- **来源应用图标**：每条通知左侧显示应用图标小方块。解析链（`src/main/notifyIconStore.ts`）：自家→`build/icon.png`；UWP 应用→`Get-AppxPackage` 找包读 `AppxManifest` 的 `Square44x44Logo` 变体（优先 targetsize-48）；已知系统应用别名（短名与 exe 名对不上时，如 `SecurityCenter`→`%SystemRoot%\System32\SecurityHealthSystray.exe`）→ 直接指向系统 exe；Win32 应用→App Paths 注册表 / 开始菜单 lnk 定位 exe 后 `SHGetFileInfo` 提 32px 图标。结果缓存 `icon-cache/notify-<短名>.png`，失败不重试。全失败也不退化成一片紫字：显示应用名首字的中性占位方块 + 应用名小字。
- **通知分组只分一层（SPEC-notify-icon-and-single-group，2026-11-14）**：默认按应用堆叠一层，图标右上角数字 = 该应用条数，预览取最新一条；点开应用**直接平铺该应用的全部具体通知**（每条自带图标/占位方块、标题、正文、相对时间、未读蓝点），不再按标题细分「会话」中间层（旧 US-040 两级堆叠已推翻）。点具体条目正文 = 打开来源应用，再点组条目 = 收起；顶部「N 条通知」仍按条数累计，不受分组影响。
- **新消息到岛横幅**：通知轮询发现新到达消息（且未读未隐藏）时，收起态岛上方弹横幅（图标+应用名+标题），5 秒自动收回；展开态不弹；首轮拉取历史不弹；多条同时到达只显示最新一条（不做队列）。**2026-11-11 修掉一个真 bug**：原来只有「展开且停在通知页」时 `NotifyPanel` 才挂载并上抛未读数，停在别的页或收起态来新通知，铃铛上的「N 条未读通知」永远停在旧值（用户原话「刚刚有通知，通知栏没有反应」）；现在 `onNotifyArrived` 里每条到达都主动重拉一次 `notify:list` 更新铃铛数字。

### 4. 日程（page 3）

- 左侧月历（可翻月、今天高亮、有安排的日期标蓝点），右侧选中那一天的安排列表。
- **日历升级（美化-04，2026-11-11）**：今天用**蓝描边 + 蓝字**标识（`box-shadow: inset 0 0 0 1.5px #64b5f6`、`color: #8fc9fb`）。**第一版是白底黑字，用户当天实机看完原话「白色背景和黑点，太丑了」——白块在纯黑岛上太跳，已换成描边空心态**；今天又恰好被选中时加一圈浅色内描边（否则默认选中的就是今天、两者样式一样会看不出今天在哪）。有安排的日子在格子底部标一个 4px 蓝点（今天格子里是亮蓝点，选中格子里是浅色点，都不用黑色）。**格内不再显示日程文字标签**——第一版做成格内塞「时间 + 标题」小标签（最多 2 条、超出「+N」），2026-11-11 用户实机看过反馈「今天那行被撑高了、不对称」，改回「只标一个点」，格子高度恢复等高对称。`aria-label` 与「日期数字就是格子文本」都没变，e2e 依赖这两点。
- 加入文本 + 可选时间；时间用自绘深色面板选择（时钟按钮弹出，时/分两列，宽 132px，**不显示滚动条**、可用滚轮在两列里滚，点面板外收起）。
- 列表每条的勾选框是圆形（未完成细描边、已完成绿圈带勾），与待办页同款，勾上时有弹跳动画。
- **每条日程带日期**：在月历上点哪天就往哪天加；旧数据（没有日期字段）启动时迁到当天，迁移前自动备份 `schedule.json.bak-<时间戳>`。
- 列表排序：有时间在前、已完成在后；过期未完成标橙（`day` 早于今天或今天已过点），无时间但已过期显示「逾期」。
- **双击条目文字改名**（与待办页同款行内编辑）：回车或点别处提交，Esc 或清空视为取消；改名只动 `text`，不影响时间/日期/完成状态/提醒状态。
- 到点弹系统提醒（每 60s 检查，只提醒当天到点的条目）。
- 待办只在选中「今天」时与日程混排（带绿色徽标，可直接勾选）；选其他日期不显示待办，副标题写「待办只在今天」。

### 5. 收起态状态栏

- 显示：岛仔（收起态 24px 布局 px，0.75 缩放后 18 视觉 px）+ 时钟 + 电量圆环 + Wi-Fi 图标 + 待办剩余数字 + 未读红点。

### 14. 全屏自动避让（US-041，判据 2026-11-08 修正）

- 前台出现全屏应用时岛自动隐藏，避免挡画面；隐藏期间把鼠标移到屏幕最顶边（4px 感应带）可临时唤回，移开自动回隐。右键菜单「暂时隐藏」是另一条独立路径（摸边无效，托盘图标恢复）。
- **全屏判据**（`src/main/fullscreenWatch.ts` 的 `watchScript()`，自适应间隔单发一个短命 PowerShell 子进程）：前台窗口**可见** ∧ **未被 DWM cloak** ∧ 类名不属于已知壳层（`Progman`/`WorkerW`/`Shell_TrayWnd`/`Windows.UI.Core.CoreWindow` 等）∧ 不是本进程窗口 ∧ 矩形覆盖整个主屏。
- **轮询降频**（SPEC-perf-poll-throttle，2026-11-14）：常态仍 1 秒一次（进全屏响应不变）；岛已进入全屏避让后降到 2 秒一次；手动隐藏时完全停掉判定 spawn，托盘恢复时立即重新起一轮。仍是「单发短命 PowerShell」，不改成长驻进程（会 hang DevTools HTTP 服务）。目的是让小工具在游戏 / 办公全屏时少反复创建子进程，不改 Electron 多进程架构、不承诺降内存。
- 2026-11-08 修正：原判据只看「矩形覆盖主屏」，把两类**不是全屏应用**的窗口也算成全屏，导致用户没开全屏岛却自己消失——① DWM 已 cloak 的 `TextInputHost`（类名 `Windows.UI.Core.CoreWindow`，rect 铺满整屏但用户根本看不见）；② 桌面 `Progman`（点桌面时它成为前台）。同时修掉「判定值不翻转就不动作」导致前台恢复后岛不自动回来的问题。
- 本机 `PrimaryScreen.WorkArea` 与 `Bounds` 相同（任务栏自动隐藏），因此**最大化占满屏幕的普通应用仍会触发隐藏**，这是 US-041 的原始设计，本轮作为回归保护未改动。
