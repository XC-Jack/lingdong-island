# 用户角色与用户故事

> 本文件负责唯一事实：谁在用、为了什么用、按什么优先级做。
> **建立方式**：按「先角色 → 再故事 → 再优先级」的顺序从头梳理（用户 2026-11-05 选定），不是把旧清单编号化。
>
> **区分两类内容**（关键）：
> - `[已确认]` = 已经实现且用户实际用过、反馈过的功能反推出来的故事。不是我说了算，是代码 + 用户实测共同确认的事实。
> - `[AI 建议]` = 我根据产品定位推导、但用户尚未表态的故事。**未经确认，只作候选**，不据此排期。
> - `[待确认]` = 角色或场景本身存在疑问，需要用户回答。

## 一、角色梳理

### 角色 1：用户本人（唯一角色）

[已确认] 本产品是单机个人桌面工具：无账号、无多用户、无云端，数据全在本机 `userData`。所以真正的「用户」只有一个——机器的使用者本人。

但这个角色内部有**三种使用状态**，它们的需求并不相同，这是梳理的重点：

| 状态 | 场景 | 关心什么 |
|---|---|---|
| **瞥一眼**（收起态，占 95% 时间） | 正在干别的事，眼睛扫过屏幕顶部 | 现在几点、还有多少电、有没有未读、待办还剩几件 |
| **处理一下**（展开态，几秒到几十秒） | 想起有件事，顺手记一下/勾一下 | 快速录入、快速勾掉、快速看一眼今天安排 |
| **搁一下**（拖放态） | 手边有个文件待会用，不想丢桌面 | 拖进来、待会能找到、不重复 |

**这三态决定了产品的核心矛盾**：收起态必须「不打扰」（否则用户会烦到关掉它），展开态必须「够快」（否则不如直接开别的软件）。

### 角色 2：岛仔（宠物）

[已确认] 岛仔不是工具，是**情绪反馈层**。它不承担任何信息功能，只在用户做了「好事」（勾掉待办、拖文件进岛）时表达开心。

[AI 建议] 岛仔的价值在于把「完成任务」这件中性的事变成有一点愉悦感的事——这是本产品区别于普通桌面挂件的关键。如果只做信息展示，用户没有理由长期留着它。

### 关于「角色」的一个待确认问题

[待确认] 博主流程通常会区分「主要角色 / 次要角色 / 管理员」。本产品没有管理员也没有次要角色，但有一个**隐含的相关方**：被岛仔情绪回应影响心情的用户自己。是否需要为「情绪价值」单独建一条故事线（而不是散落在各功能里），需要用户决定。

## 二、优先级判据

先定判据，再给故事定级，避免拍脑袋。

| 级别 | 判据 | 处理方式 |
|---|---|---|
| **P0** | 缺了它产品不成立（打开就发现不能用），或会造成数据/信任损失 | 必须做，做完才能交付 |
| **P1** | 缺了它用户会明显不爽、但还能用；或高频路径上的摩擦 | 当前版本内做 |
| **P2** | 锦上添花，能提升体验但用户不会因此不用 | 排期靠后，有空再做 |
| **不做** | 与产品定位冲突，或投入产出明显不划算 | 明确记录否决理由，避免反复讨论 |

**判定口径**：「用户会不会因为这个功能缺失而关掉它」——会，就是 P0/P1；不会，就是 P2。
