# 新窗口怎么接手（小白版）

> 给用户看的交接说明：换一个新会话窗口继续做这个项目时，把下面对应的一句话发进去就行。
> 本文件不承载规则，规则在 `docs/工程规则.md`，状态在 `docs/状态.md`。

## 一、为什么换窗口不会丢东西

所有「事实」都已经写在文件里，不在聊天记录里。新窗口的 AI 不知道我们聊过什么，但它能读文件：

| 你担心的事 | 实际存在哪 |
|---|---|
| 做到哪了、下一步做什么 | `docs/状态.md` |
| 产品是什么、有哪些功能、什么优先 | `docs/facts/` 8 份文档 |
| 开发纪律（分支、SPEC、验收） | `docs/工程规则.md` |
| 以前的历史记录 | `docs/archive/`（只读） |

新窗口只要读这几个文件，就和现在这个窗口知道的事一样多。

## 二、开新窗口时，发这一句就够

```text
项目在 D:\Users\honor\Documents\Project\灵动岛。
先读 AGENTS.md、docs/状态.md、docs/工程规则.md，然后按 docs/状态.md 的「下次开工先做什么」继续。
当前任务：US-019 置物架文件失效提示。先建 SPEC 再动手。
```

想让它做得更贴合，可以再加一句你关心的点，比如「界面别太花」「先别打包」。

## 三、这个框架到底在跑什么（一句话一步）

按顺序做五步，做完一件再下一件：

| 步 | 谁做 | 做什么 | 做完留下什么 |
|---|---|---|---|
| 1 | 你 + AI | 商量要做什么，写进用户故事 | `docs/facts/用户角色与用户故事.md` 多一条 |
| 2 | AI | 写 SPEC：这次改什么、怎么算做对 | `docs/Spec/SPEC-xxx.md` |
| 3 | AI | 开分支、写代码、自己测一遍 | 一个固定提交 + 自检记录 |
| 4 | 另一个 AI 窗口 | 按 SPEC 一条条核对这个提交 | 验收记录 |
| 5 | 你点头后 | 合回 `main`、重新打包、装到你机器上 | 新版能用的岛 |

**关键在 3 和 4 分开**：写代码的人不许自己宣布「通过」，否则等于没检查。这也是你换新窗口的最好理由——新窗口天然没参与过开发，正好当验收方。

## 四、你只需要记住三个词

- **SPEC**：这次任务的说明书。没有它就不许开工。
- **分支**：草稿纸。`main` 是正式版，改动先在草稿上做，验收完才誊回去。
- **打包安装**：让改动出现在你屏幕上。只跑 `npm start` 你看不到，必须 `npm run dist` 装一遍。
