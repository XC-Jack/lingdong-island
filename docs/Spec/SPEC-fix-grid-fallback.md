# SPEC-fix-grid-fallback：修正展开态兜底尺寸与注释（丙类）

- 日期：2026-11-27
- 分支：`fix-grid-fallback`
- 来源：2026-11-27 批量独立验收。子代理怀疑「网格 362 会被旧的兜底尺寸 248 裁切」，我实测后确认**不会裁切**（展开后窗口 272×256、岛 272×255，兜底值在渲染层上报真实尺寸之前只有一瞬），但发现兜底值本身和注释都已过时。

## 一、目标

把 `src/main/index.ts` 里展开态兜底尺寸与注释同步到当前组件网格的实际高度，避免后续读代码的人被误导，也避免「兜底值恰好生效时窗口比岛矮一截」的隐患。

## 二、修改范围

只改 `src/main/index.ts` 的两处：

| 位置 | 现状 | 改为 |
|---|---|---|
| `:64-65` 注释 | 「初始值取组件网格的固定尺寸（340×330 布局 px ×0.75）」 | 362 布局 px（视觉 271.5） |
| `:66` `expandedSize` 初值 | `{ width: 255, height: 248 }` | `{ width: 255, height: 272 }` |

**不动** `EXPANDED_MIN` / `EXPANDED_MAX` 的上下限（那是 clamp 边界，与兜底初值不同用途）。

## 三、预期行为

1. 注释与初值一致：都指当前组件网格。
2. 兜底值生效时（渲染层还没上报真实尺寸的极短窗口内），窗口高度不再比岛矮 24px。
3. 不改变任何正常路径的行为——渲染层第一次 `setExpandedSize` 到达后仍以实测值为准。

## 四、必要依赖

无。

## 五、验收条件

| 编号 | 条件 |
|---|---|
| A1 | `src/main/index.ts` 注释写 362、初值写 272 |
| A2 | `npm run typecheck` EXIT=0 |
| A3 | `npm run build` EXIT=0 |
| A4 | 探针：展开网格时窗口 256×273、岛 255×271.5（与改动前一致，因为兜底值不参与正常路径） |
| A5 | `e2e-widget-drag` 与 `e2e-pages-custom` 通过（`expand-clip` 没有独立 e2e 脚本，当时用 `.tmp/repro-expand.mjs` 逐帧探针验的，本项改由 A4 的尺寸探针覆盖） |

## 六、不做什么

- 不改 `EXPANDED_MIN` / `EXPANDED_MAX`。
- 不改渲染层的尺寸上报逻辑。
- 不改任何 CSS。
- 不合并 `main`、不打包、不推送。

| 验收项 | 命令 | 结果 | 证据 |

| A2 | `npm run typecheck` | **通过** | `typecheck:node` 与 `typecheck:web` 均无输出，EXIT=0 |

### 未验证项

1. **兜底值真正生效的那一瞬没有观测到**：渲染层在展开前就上报真实尺寸，正常路径下兜底值只存在于 `boot` 到第一次 `setExpandedSize` 之间，探针采样不到这个窗口期。改动是「让兜底值更接近真实值」，不是修复可复现的缺陷。
2. **没有跑逐帧探针（`.tmp/repro-expand.mjs`）**：那是 `SPEC-expand-clip` 的一次性脚本，本轮没有重建。A4 只验证了最终尺寸，没有验证「展开全程岛不超出窗口」。
3. **没有跑全量 e2e**：只跑了 `e2e-widget-drag` 与 `e2e-pages-custom` 两个直接相关脚本。

### 结论

改动前兜底高度 248 比实际 271.5 矮 23.5，若兜底值恰好生效，窗口会裁掉网格底部约 24 视觉 px。改动后兜底值与实测一致，这个隐患消除。**但这是预防性修正，不是修复已观测到的 bug** —— 之前没有观察到裁切，因为渲染层上报总是赶在展开之前。
