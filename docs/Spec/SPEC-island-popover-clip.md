# SPEC：岛内浮层被岛/窗口裁掉（置物架视图菜单、时间选择器）

- 建立日期：2026-11-22
- 基线：分支 `perf-no-sync-ps`（`fb15440`）。**不是 `main`**：用户正在看的就是这个分支的预览版，两处改动要一起看；`main` 仍是 `dfc4f20`。
- 任务分支：`island-popover-clip`
- 用户原话（2026-11-22，附两张截图）：「现在置物架，这个选择我往下选不了，这是第二批要做的吗；如截图二，我发现这个时间好像也有问题」

## 〇、结论先说

**不是第二批**（第二批是切页时窗口尺寸的 500 ms 补间动画）。这是另一个独立缺陷：
**岛内绝对定位的浮层不参与岛的内容高度，越过岛底就被 `.island { overflow: hidden }` 裁掉，而窗口尺寸又刚好等于岛尺寸——被裁掉的那部分落在窗口外，指针事件根本到不了。**

## 一、目标

岛内的两个浮层（置物架「视图」菜单、待办/日程的「时间选择」面板）打开时，岛和窗口自动长到刚好包住它；关掉后缩回原样。浮层里的每一项都看得见、点得到。

## 二、问题定位（[实测]，隔离实例 CDP 量取）

| 场景 | 测到的数 |
|---|---|
| 置物架页（0 个文件） | 窗口 256×**156**，岛 155 |
| 打开「视图」菜单 | 菜单 102–189，其中 **小图标 146–168、列表 168–189 在窗口（底 156）之外** → 点不到（用户截图里只剩前两项） |
| 待办页打开「时间选择」 | 面板 104–**242**，窗口只有 188 → **24 个小时里只有 3 行可达**（00/01/02），分钟列 12 个里也只有 3 个 |
| 两列是否对齐 | 列高 113、单元格 17、两列首行 top 完全相同 → **两列本身是对齐的**，用户看到的「怪」是下半截被裁 + 两列各自滚动 |

根因两条，缺一不可：

1. `.shelf-view-pop` / `.sched-time-pop` 都是 `position: absolute`，不撑高父级；岛是 `height: max-content`，所以岛不长大。
2. 主进程窗口尺寸 = 渲染层上报的岛尺寸；**而岛的 ResizeObserver 用默认的 `content-box`**，只改 `padding` 时**不触发**回调——即使让岛靠 padding 长高，窗口也不会跟着长。

## 三、修改范围

| 文件 | 改什么 |
|---|---|
| `src/renderer/src/popFit.ts`（新） | `fitIslandToPopover(pop)`：打开浮层时量出「浮层底 − 岛底」的视觉像素差，按实测缩放比例换算成布局 px 写进岛根的 `--pop-extra`；关闭时清掉并取消排队测量 |
| `src/renderer/src/styles.css` | `.island.expanded` 增加 `padding-bottom: calc(20px + var(--pop-extra, 0px))`（原本是 `padding: 20px 16px`） |
| `src/renderer/src/App.tsx` | ① 岛尺寸上报的 `ResizeObserver` 改为 `ro.observe(el, { box: 'border-box' })`；② ShelfPanel 的视图菜单、TodoPanel 与 SchedulePanel 的时间面板各加一个「打开时调用 popFit」的 effect（菜单节点加 ref） |
| `docs/facts/功能清单.md` | 置物架视图、时间选择两条补一句「浮层打开时岛自动让高」 |
| `docs/状态.md` | 顶部一句话状态 |

## 四、预期行为

1. 空置物架点「视图」→ 岛向下长到约 195，四项全部可见可选；选完/关掉缩回 156。
2. 待办页点时钟 → 岛长到约 243，时间面板完整落在岛内；小时列滚到底能选到 23:00，分钟列同理；关掉缩回 188。
3. 日程页的同一面板同样生效（该页内容高，多数情况不触发）。
4. 窗口变高仍走既有的 `island:set-expanded-size` → `animateTo`，不新增 IPC、不改主进程。
5. 关闭浮层后 `--pop-extra` 被清空，岛/窗口回到原尺寸（不留白）。
6. 收起态、其它页面、横幅、点击穿透等既有行为不变。

## 六、验收条件

- A1 `npm run typecheck`、`npm run build` 通过。
- A2（隔离实例 CDP）空置物架 + 打开视图菜单：窗口高 ≥ 菜单底边，**四项全部可达**（`getBoundingClientRect().bottom ≤ innerHeight`）。
- A3（同上）待办页 + 打开时间面板：窗口高 ≥ 面板底边；小时列 `scrollTop = scrollHeight` 后「23」可见且点击后 header 显示「已选 23:00」。
- A4 两处关掉浮层后窗口回到原高（置物架 156、待办 188），`--pop-extra` 为空。
- A5 回归：`e2e-todo-today` / `e2e-shelf-view-pref` / `e2e-schedule` / `e2e-schedule-scroll` / `e2e-head-order` / `e2e-banner-fit` 全过。

## 七、不做什么

- 不动窗口尺寸补间的时长/曲线（仍是第二批的 500 ms），浮层打开时长度变化会跟着跑一次补间。
- 不把浮层改成 `position: fixed` / portal / 原生菜单。
- 不改时间面板的「两列各自滚动」交互（两列是对齐的，只是可见区域曾被裁掉）。
- 不碰主进程窗口逻辑与 IPC。
- 不合并回 `main`、不打包、不发版。

### 8.2 过程中踩到的两个坑（记录，避免以后重犯）

1. 第一次实现把「视觉 px → 布局 px」换算方向写反了（除了 1.33 而不是乘 0.75），岛只长了 21 px，仍不够。
2. 修好换算后岛长高了，但**窗口不跟**：`ResizeObserver` 默认观测 `content-box`，只改 `padding` 不触发回调。改成 `box: 'border-box'` 后才通（窗口尺寸本来就该跟岛外框走）。

### 8.3 未验证的范围

1. **打包版已验（2026-11-22 合并打包后补测）**：安装版起 CDP 实测——空置物架页打开视图菜单窗口 **156 → 195**，四项全部可达；关掉回到 156、`--pop-extra` 为空；时间面板窗口 **188 → 243**，滚到底「23」可见、点击后显示「已选 23:00」。
2. 只在 125% 缩放的机器上看过；100%/150% 缩放下的换算走的是实测比例（`offsetHeight / rect.height`），理论上自适应，但没有实机核对。
3. 浮层打开/关闭时窗口会跟着跑一次 500 ms 补间（第二批的范围），弱机器上的体感未测。
4. 日程页的时间面板在「内容刚好很矮」的组合下是否也能撑开，只按同一份代码推断，没有单独构造矮内容场景。
