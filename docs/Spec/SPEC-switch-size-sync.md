# SPEC：切页时窗口尺寸与内容不同步（岛被窗口裁掉）

- 建立日期：2026-11-24
- 基线：`main` `90eeac7`
- 任务分支：`switch-size-sync`
- 承接：`SPEC-island-window-resize` 第七节「未验证：弱 GPU/软件合成机器上的真实体感」——本轮由用户在另一台电脑上实测确认。

## 〇、问题（[实测]，2026-11-24）

用户回传手机拍屏视频（13.7 s，1280×720）：切页瞬间岛被切成一块、左右内容缺失、两套画面错开叠在一起。

本机隔离实例 CDP 实测（2026-11-24，`main` `90eeac7`）——待办页切到日历页：

| 时刻 | 窗口 | 岛 rect | 内容 rect | 说明 |
|---|---|---|---|---|
| t=3499 | 256×188 | 1,0,255,187 | 13,76,229,70 | 切换前 |
| t=3524 | 256×188 | **-63,0,381,272** | -50,79,356,155 | 内容已换，窗口没动，岛左右各被裁 63px |
| 3524–3591 | 256×188 | -63,0,381,272 | 同上 | **持续约 67–84 ms** |
| t=3608 | 383×274 | 1,0,381,272 | 14,76,356,155 | 窗口才跟上 |

`--disable-gpu`（软件合成，模拟弱机）复测同款：3540→3633，约 93 ms。

根因链：
1. 切页 → `.page-fade` 换页 → `.island` 立即变成新页尺寸（`width/height: max-content`，**没有** CSS 过渡）；
2. 窗口尺寸靠 `ResizeObserver` 上报，而上报有 **80 ms 去抖**：
   `src/renderer/src/App.tsx:3166-3193`；
3. 主进程收到才 `setBounds`：`src/main/index.ts:537-558`。
4. 于是在「岛变大」到「窗口变大」之间存在 80 ms+ 的窗口期，岛被窗口裁掉。`SPEC-island-window-resize` 把窗口从「500 ms 分 9–19 次追」改成「一次到位」后，单次跳变幅度变大（本例宽 127 px），弱机/软件合成上合成滞后更长——用户视频里同一现象持续 0.2–0.4 s。

## 一、目标

**切页时，用户永远看不到「岛比窗口大」的那一帧。** 具体：

1. 切页时立即测量新页尺寸并上报，不再等 80 ms 去抖。
2. 新页内容等主进程确认窗口已改好（IPC 回执）后再淡入；回执 300 ms 未到则兜底显示，绝不卡空白。
3. 非切页的尺寸变化（列表增减、浮层撑高等）维持现有 80 ms 去抖，不改行为。

## 二、修改范围

| 文件 | 改动 |
|---|---|
| `src/main/index.ts` | `island:set-expanded-size` 由 `ipcMain.on` 改 `ipcMain.handle`，处理完返回当前尺寸作为回执；其余逻辑不变 |
| `src/preload/index.ts` | `setExpandedSize()` 由 `send` 改 `invoke`，返回 `Promise` |
| `src/renderer/src/App.tsx` | 新增切页 reveal 状态机：`pageAnim` 变化时先测尺寸上报，拿到回执（或 300 ms 超时）再显示新页；`page-fade` 加 `page-ready` 类 |
| `src/renderer/src/styles.css` | `.page-fade` 初始 `opacity: 0`，`.page-fade.page-ready` 才播淡入（`animation-fill-mode: both`）；reduced-motion 分支同步 |
| 类型声明 | `window.island.setExpandedSize` 返回类型跟着改（`env.d.ts` / `shared/types.ts` 里现有声明处） |

## 三、预期行为

1. 切页：点击后同一帧量出目标尺寸 → 立刻上报 → 主进程改窗口 → 渲染层收到回执 → 新页淡入。正常情况下回执往返 1–10 ms，用户只看到一次正常切换。
2. 回执超时（主进程忙/异常）：300 ms 后强制显示，不出现永久空白。
3. 展开/收起：不变（仍走 500 ms 补间）；展开动画进行中切页，回执会在补间重起后返回，内容照常显示。
4. 收起态切页（不可见）：不进入 reveal 流程，直接显示。
5. 非切页变化：维持 80 ms 去抖。

## 四、必要依赖

无新增依赖。

## 五、验收条件

- A1 `npm run typecheck`、`npm run build` 通过。
- A2（隔离实例 CDP，本机 + `--disable-gpu` 各一次）待办页 → 日历页切页采样 120 帧：**「岛 rect 超出窗口 innerWidth/innerHeight」的帧数 ≤ 1**（改前 ≥ 3，实测 67–93 ms）；最终岛尺寸 = 窗口尺寸（±1）。
- A3 回执超时兜底：临时把主进程 handler 人为阻塞 >300 ms（或探针直接模拟不返回），确认 300 ms 后内容仍可见。
- A4 回归：`e2e-head-order`、`e2e-collapse-order`、`e2e-todo-today`、`e2e-schedule-day`、`e2e-bell-notify`、`e2e-shelf-view-pref`、`e2e-banner-fit`、`perf-click-latency`。
- A5 切换后连续 5 次翻页（含快速连点）不出现永久空白、不出现页面残留。

## 六、不做什么

- 不做「按各页历史尺寸预扩窗口再切内容」的缓存方案（本轮先做核心同步，观感不够再另开）。
- 不把窗口改成固定大尺寸（会挡下面窗口点击，已决策不做）。
- 不改 `.island` 的 CSS 过渡、不改展开/收起补间、不改非切页路径的 80 ms 去抖。
- 不改各页内容尺寸/布局。
- 不合并回 `main`、不打包、不发版（等用户决定）。

### 7.2 未验证 / 限制

- **用户那台电脑**（真实弱机 + 动态壁纸）：无法直接测，只能等装机后用户体感确认。
- 120/144 Hz 显示器下的表现未测。
- 切页后页面若因异步数据二次改变尺寸（如通知列表回填），仍走原 80 ms 去抖，可能出现 1–2 帧窗底留白；本次未处理（SPEC 第六节已列为后续）。
- 兜底路径是用「临时把主进程返回延迟 400 ms」实测的，不是真让 IPC 永不返回。
