# SPEC：切页快速点击卡顿优化

- 建立日期：2026-11-24
- 基线：`island-no-pager` `9a2d3d4`
- 任务分支：`island-no-pager`
- 用户反馈：「做的还行，动画也可以，小瑕疵就是点的太快感觉上有点卡，优化一下」。

## 一、目标

连续快速点开/返回页面时不出现可见的裁切、空白和错位；正常的展开/收起与 340ms 缩放动画保持不变。

## 二、修改范围

| 文件 | 改动 |
| --- | --- |
| `src/renderer/src/App.tsx` | 切页时临时加 `nav-snap`；返回网格前按缓存扩窗；网格视图下立即上报尺寸；记住「打算用的窗口尺寸」供 `pageReady` 判断 |
| `src/renderer/src/styles.css` | `.island.expanded.nav-snap { transition: none }` |
| `docs/状态.md` | 本轮条目 |
| `docs/facts/视觉设计规范.md` | 固定页面尺寸一节补切页规则 |

## 三、预期行为

1. 返回网格时窗口先扩到网格尺寸，不再出现网格底部被窗口裁掉约 100ms 的现象。
2. 切页瞬间岛的宽高过渡关闭（`nav-snap`，120ms 后移除），与窗口的一次性 `setBounds` 对齐；收缩方向岛不会比窗口大，`pageReady` 量到的是目标尺寸而不是过渡起点。
3. `pageReady` 判断「放不放得下」时把刚上报、尚未被主进程执行的目标尺寸算进去，已经提前扩窗的页面不再多等一次回执。
4. 展开/收起仍走 500ms 主进程补间；点组件/返回的 340ms FLIP 动画、120ms 淡入不变。

## 四、必要依赖

无。

## 五、验收条件

- A1 `typecheck` / `build` 通过。
- A2 探针：快速往返（每步 40–60ms，含网格 ⇄ 五个页面）时「岛比窗口高」的帧数显著下降，且不再出现 ≥80ms 的裁切窗口。
- A3 展开仍是渐进展开（主进程补间），没有被 `nav-snap` 误伤。
- A4 回归：页面管理、待办、日程、通知、置物架、音乐 e2e 全过。
- A5 用户预览确认手感。

## 六、不做什么

- 不改 `main` 的窗口补间时长与 `applyBoundsNow` 策略。
- 不为切页引入固定大窗口或鼠标穿透（会挡住岛周围桌面点击）。
- 不改 FLIP/淡入动画时长与观感。
- 不合并 `main`、不打包、不发版。
