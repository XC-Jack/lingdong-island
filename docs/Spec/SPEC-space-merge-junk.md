# SPEC：系统垃圾与需要管理员合并为一张清单

- 创建：2026-11-20
- 分支：`space-merge-junk`（从 `main` `0f11b27` 拉出）
- 前置：`SPEC-space-system-junk`、`SPEC-space-admin-cleanup`、`SPEC-space-layout`

## 1. 目标

用户认为「系统垃圾」和「需要管理员」两节内容重复（都是系统垃圾，只差要不要授权），希望合成一张清单，减少重复的标题、说明和按钮。

## 2. 修改范围

- `src/renderer/src/settings/SpaceSection.tsx`：新增 `JunkPanel` 取代原「系统垃圾」面板与 `AdminPanel`（后者删除）；`CleanupPanel` 去掉只服务于系统卡的 `nested` 分支。
- 文档：`docs/facts/功能清单.md` 第 16 节、`docs/状态.md`、`docs/facts/本机约束与踩坑.md`（测试规则）。
- 不改：`src/main/`、`src/shared/types.ts`、`preload`、IPC 与数据结构。

## 3. 预期行为

- 「系统」卡片内两节：**系统垃圾**（8 项：4 项普通 + 4 项需要管理员）与**卸载残留**（不变）。
- 合并后的清单里，需要管理员的 4 项在名字后面带一把**小锁图标**（`aria-label` 与 `title` 为「需要管理员授权」），不逐行写文字；说明只保留在卡片开头一句。大小仍按原规则显示（普通项显示实际大小，管理员项读不到时显示「无法统计」）。
- 「系统垃圾」小节**不再单独写说明**，避免与卡片开头重复。
- 勾选、合计（可清理 / 已选）跨两类一起算。
- 点「清理选中项」：先清普通项（不弹 UAC）；若勾了管理员项，再弹**一次** UAC 清那些项。
- 用户拒绝 UAC：普通项的结果保留，提示里写明「已取消管理员授权，需要管理员的那几项没有动」。
- 只勾普通项时全程不弹 UAC；只勾管理员项时直接弹。
- 扫描仍为渐进式：普通项逐项填数字，管理员项一次返回。

## 4. 必要依赖

无新增依赖。

## 5. 验收条件

1. 「系统」卡里只有两节，「系统垃圾」一节 8 行，管理员行带标签。
2. 勾选普通项与管理员项时，合计同时变化；普通行与管理员行互不影响按钮可用性。
3. 只勾普通项 → 清理释放空间、无 UAC。
4. 勾了管理员项 → 普通项先清完，再弹一次 UAC；取消后提示准确。
5. 清理后大小就地更新，清空的项自动取消勾选。
6. 卸载残留一节的行为不变。

## 6. 不做什么

1. 不合并「卸载残留」：它要先备份、可撤销，行为不同。
2. 不改主进程规则与白名单。
3. 不改需要管理员的四项内容与判据。
