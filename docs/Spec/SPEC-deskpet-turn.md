## 起因

用户 2026-11-12 反馈（m01141）：「还有就是能不能做3d的」。

给了三条路（真 3D 建模 + Three.js / 四视图多角度切换 / 图片加阴影伪造），
用户先选第一条（m01295「我想走第一条」），在给出五步排期后改选第二条
（m01339「那还是先做第二条也可以，反正后面应该也可以再弄3d的对吧」）。

本 SPEC 只做第二条：**四视图转身**。以后要上真 3D 时另开 SPEC。

## 一、目标

让「我的原图」这套皮肤不再是钉死的一张正面图——隔一段时间自动转个身
（正面 → 侧左 → 背面 → 侧右 → 回正面），看起来像有体积的东西在动。

## 三、预期行为

> **2026-11-12 第二轮改动（提交 `154c00a`）**：用户看到第一版后反馈
> 「我希望我可以用鼠标来让它转身，22 秒转一次感觉很怪」。
> **自动转身整个删掉了**，改成鼠标拖动驱动。下面的 2~4 条已按新行为重写。

1. 设置 → 桌宠 → 选「我的原图」。
2. 桌宠出现在独立小窗口（或岛里展开态）时，**静止面对你**，不会自己动。
3. 按住它往右拖：顺时针转身（露出右脸）；往左拖：逆时针。
   每 110px 转四分之一圈，转角累加，松手停在当前那一面。
4. 拖过一整圈回到正面，所以拖多远都不会「转飞」。
5. 双击它：转回正面（拖歪了不用去设置里折腾）。
6. 视图之间是淡入淡出（170ms），不是硬切。
7. 四个视图**高度一致、脚底对齐**，转身过程中身形不会忽高忽低。
8. 侧面转到右边时用同一张侧图水平镜像，不额外做第四张图。

## 四、必要依赖

脚本在 `.tmp/cutout_views_v2.py`（辅助文件，不入库）。

## 五、验收条件

- [ ] 条件 1：原图皮肤渲染出四个 `.pet-photo-layer`，`data-layer` 依次是 `front,side-l,back,side-r`
- [ ] 条件 2：四层渲染高度差 ≤ 1px
- [ ] 条件 3：四层顶边 y 一致（脚底对齐的另一面）
- [ ] 条件 4：显式触发 `pet:turn` 时，`data-turn-view` 按 `front→side-l→back→side-r→front` 轮换
- [ ] 条件 5：**没有自动转身**——静置 3 秒以上视图不变（第二轮改动后的新要求）
- [ ] 条件 6：往右拖 110px 露出 `side-r`、再拖 110px 到 `back`、往左拖 220px 回 `front`
- [ ] 条件 7：拖不到半格（50px）不换面
- [ ] 条件 8：双击转回 `front`
- [ ] 条件 9：侧图在 `side-r` 档是水平镜像的，不是重复用同一朝向
- [ ] 条件 10：`npm run typecheck` 与 `npm run build` 通过
- [ ] 条件 11：原有全套 e2e 不回归（deskpet / m2 / head-order / collapse-order / settings-shell）

## 六、不做什么

- 不做真 3D（Three.js / glTF 建模）——用户以后想要时另开 SPEC。
- 不做自由走动（`petMode: 'free'` 仍是禁用档）。
- 不做随情绪换姿势（`happy`/`sleepy`/`surprised` 四视图都有，本轮只切视图不切情绪动作）。
- 不做岛内 tiny 尺寸的转身。
- 不做逐帧动画（那是视频或 spritesheet 的活，成本高一个量级）。
- 不为第四视角单独做图（用镜像）。

### 踩到的三个坑（写下来免得下次重踩）

**坑 1：本机 `prefers-reduced-motion: reduce` 是开着的。**
第一版按常规写法尊重它（`if (matchMedia('(prefers-reduced-motion: reduce)').matches) return`），
结果转身直接被跳过、`step` 卡在 0。注册表佐证
`HKCU:\Control Panel\Desktop\WindowMetrics\MinAnimate = 0`。
第二版改成拖动驱动后这个判断本身就不需要了——用户主动拖是操作反馈，不是装饰动画。

**坑 2：探针截图抓在淡入淡出中间，截到两张半透明叠一起的帧。**
`front op=0.2155 + side-l op=0.7844` 同时可见，看起来像鬼影。
解法是分两段：**转身正确性靠 `data-turn-view` 序列判**（dataset 是瞬时值，不受过渡影响），
**视觉效果靠强制单层显隐再截**（`style.setProperty('opacity', ..., 'important')` + `transition: none`）。
跟帧截图这条路走不通——CDP 截图有 100ms 级延迟，等抓完已是下一帧。

**坑 3（第二轮新增，最容易重踩）：算拖动位移必须用 `screenX`，不能用 `clientX`。**
这个窗口是跟着光标走的（主进程每 16ms 把窗口挪到光标位置），
所以光标在窗口内的相对位置几乎不变，`clientX` 全程是同一个数，
拿它算位移永远是 0，拖动转身完全没反应，而且看起来像「事件没注册」而不是「算错了」。
`screenX` 是屏幕坐标，不受窗口移动影响，只有它在动。e2e 的 P9f 也必须给
`screenX` 赋值（给 `clientX` 测不出来）。

### 已知的素材缺陷（不是 bug）

背面是纯后脑勺、没有眼睛。转身转到背面时眼睛会消失，这是用户给的原图
（四视图渲染图）本身如此，不是抠坏了。用户 m01596 已明确说
「背面就是没有眼睛的，你不用见怪」——所以这条**不需要修**，
只在文档里记着，免得以后有人当成 bug 去「修」。
