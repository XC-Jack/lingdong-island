# SPEC：通知页紧凑化 + 空白条目消除

## 一、目标

用户 2026-11-07 反馈两点：①通知条目太大，一屏显示条数少；②部分条目只剩
时间、内容空白（用户第二张截图），这些空白条目「基本多余」要消掉。

## 二、修改范围

- `src/renderer/src/styles.css`：通知列表 `.notify-item` / `.notify-body` /
  `.notify-title` / `.notify-text` / `.notify-icon` 的间距、行高、字号收紧
  （条目高度约从 55px 降到 ~44px）。
- `src/renderer/src/App.tsx`：NotifyPanel 渲染前过滤 `title` 与 `body`
  皆空的条目（防御性兜底——数据库层已过滤 `toastCondensed`，此处兜住
  「toast 但无文本」的漏网数据），空条目不再占一行。
- （不加新文件、不动主进程。）

## 三、预期行为

- 通知列表每条更紧凑，一屏可见条目数明显变多。
- 标题和正文都为空的通知不再渲染成空白卡。
- 有图标的条目布局不变；点条目打开来源应用的行为不变。
- 「32 条通知」计数仍按后端返回条数（不为空条目减少）。

## 四、必要依赖

无新增依赖。

## 五、验收条件

1. typecheck / build 通过。
2. e2e（复用 notify 相关脚本）跑通；新增断言：注入一条空 title/body 的
   通知数据时列表不渲染空白行。
3. 真机观察：条目高度变小，无空白条目（用户验收）。

## 六、不做什么

- 不改通知的读取、水位、横幅逻辑。
- 不做「已读变灰」等新样式语义（空白条目直接消失即可）。
- 不动乱码历史数据（「锟斤拷」条目是当年测试脚本编码问题，属数据而非应用；
  用户「清空」即可清掉）。
- 不改主进程 SQL 过滤条件（已过滤 toastCondensed）。
