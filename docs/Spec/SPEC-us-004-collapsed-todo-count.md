## 一、目标

让岛在**收起态**（那根矮条）就能看出待办还剩几件。现在想知道还有多少事没做，必须把鼠标移上去展开、切到待办页才看得到，等于「瞥一眼」这个核心场景漏了一半。本次只做一件小事：收起态多一个「还剩 N」的小标记，数据跟待办页始终一致。

## 三、预期行为

1. 岛处于收起态、且待办里**有未完成的条目**时，在最右侧（电量环右边、未读红点左边）出现一个待办标记：一枚对勾小图标 + 数字，数字 = 未完成条数。放在最右是因为它是最次要的信息，靠边不抢时钟和电量的位置。
2. 鼠标悬停在该标记上，提示「还有 N 件待办（共 M 件）」。
3. 待办全部完成时，收起态**不显示**这个标记（不占地方、不催人）。
4. 一条待办都没有时也不显示。
5. 从展开态收回时标记数字是最新的：在待办页勾掉一条再移开鼠标收回，数字立刻减一；新增一条后再收回，数字加一。
6. 首次启动（程序刚起来就是收起态）时数字已经是正确的，不需要先展开一次。
7. 数字随内容自动变宽收窄（`1` 与 `12` 宽度不同），不出现截断或换行。

## 六、不做什么

- 不做「收起态显示待办第一条内容」「滚动播报待办」之类扩展，只说剩几件。
- 不做实时监听：不挂 `setInterval` 轮询，也不做文件监听；只在首次挂载与每次收回时现算一次。
- 不在收起态做点击交互（点标记不展开、不跳页）——收起态整条的行为保持现状，避免误触。
- 不改展开态头部的 `n/m` 完成度显示。
- 不合并回 `main`、不打标签、不发布（合并要用户单独授权）。
