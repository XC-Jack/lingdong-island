# SPEC：删除「摸边唤回」（避让期间光标到屏幕顶边不再叫出岛）

- **建立日期**：2026-11-25
- **基线提交**：`eaf4af7`（分支 `fix-avoid-self-foreground`）
- **关联**：`SPEC-no-reveal-in-fullscreen.md`（2026-11-18 先对真全屏禁用）、`SPEC-avoid-show-attribution.md`（闩锁）、`SPEC-avoid-mode-and-latency.md`（三档）

## 一、目标

用户 2026-11-25 连续两次反馈同一现象：

> 「不是说了 f11 和全屏不用唤醒吗」
> 「挡位一的时候，全屏如截图依旧可以唤醒」

截图里的前台是**最大化**窗口（`GetWindowRect = -9,-9,1929,1149`、`IsZoomed=True`，判定码 `Z`），不是 F11 全屏。旧行为：`maximized` 档在 `Z` 下按设计允许「光标顶到屏幕最顶边 4px → 临时叫出岛」（设置页文案原文就写着这句）。日常使用中光标顺路划过顶边就会把岛叫出来挡住画面，用户认为这是 bug。

**核实记录（本机实测）**：

| 场景 | 前台窗口 | 判定 | 旧行为 |
|---|---|---|---|
| Chrome `--start-fullscreen`（独立 profile） | `0,0,1920,1200`、`IsZoomed=False` | `F` | 岛隐藏，且**不会**被光标唤回（2026-11-18 起已禁） |
| 最大化窗口（用户截图） | `-9,-9,1929,1149`、`IsZoomed=True` | `Z` | 岛隐藏，但**光标顶边会唤回** |
| 档位② + 最大化 | 同上 | `Z` | 岛不隐藏（该档定义如此） |

结论：真全屏的判定与禁唤回都正常；用户看到的「唤醒」全部发生在最大化场景。

## 二、修改范围

| 文件 | 改动 |
|---|---|
| `src/main/fullscreenWatch.ts` | 删除 `maybeRevealByCursor()` 及其调用、`revealArmed` 闩锁、`REVEAL_REARM_Y`；文件头与状态机注释改为「避让期间无摸边唤回，只能托盘/横幅显式找回」；`checkCursor`（临时现身后移开回隐）保留 |
| `src/renderer/src/settings/SettingsApp.tsx` | 档位①文案去掉「鼠标移到屏幕最顶边 4px 可以临时叫出来」，改为「点托盘图标」 |
| `scripts/e2e-fullscreen-avoid.mjs` | A4 由「最大化下摸边唤回=true」改为「不唤回=false」；A5 改为「光标移开仍保持隐藏」；新增 A2b「真全屏下摸顶边不唤回」 |
| `docs/facts/功能清单.md`、`docs/状态.md` | 同步 |

**明确不改**：三档判定（`decision()`）、真全屏/最大化的区分方式、托盘「显示灵动岛」与横幅两条显式现身路径、临时现身后的移开回隐、去抖与自愈逻辑。

## 三、预期行为

1. 任何避让状态（最大化或真全屏）下，光标移动到屏幕最上边**不会**让岛出现；光标停在顶部也不会。
2. 要看岛：点托盘图标、托盘右键「显示灵动岛」，或等通知横幅——这三条保持原样。
3. 从托盘恢复时若前台仍在避让：岛临时现身，光标在岛上保留、移开后回隐（与删除前一致）。
4. 普通窗口置前时岛照常可见，摸顶边也不影响（本来就没有避让）。

## 四、必要依赖

无。删除代码后还少了一个每 150ms 执行的分支与一个闩锁变量；心跳里的光标坐标仍被 `checkCursor`（临时现身回隐）与 `island:edge-leave` 使用。

## 六、不做什么

- 不新增开关（没有再做一个「允许摸边唤回」的选项）——用户要的是彻底不唤回；将来若需要，再基于本 SPEC 回滚。
- 不改「最大化算不算避让」的判定，不动档位②「最大化不隐藏」的定义。
- 不处理「位置偏移 / 显示不全」。
