## 1. 目标

在设置「空间」页增加第二组「系统垃圾」，清理 Windows 和其他软件留下的、**不需要管理员权限**的垃圾：临时文件、崩溃转储与错误报告、缩略图缓存、回收站。用户 2026-11-20 明确选「先不带需要提权的项」。

## 3. 预期行为

系统垃圾四项（白名单固定）：

1. **临时文件**：`app.getPath('temp')` 下的内容（`%TEMP%`）。正在被其他程序占用的文件跳过，不报错。
2. **崩溃转储与错误报告**：`%LOCALAPPDATA%\CrashDumps`、`%LOCALAPPDATA%\Microsoft\Windows\WER\ReportArchive`、`ReportQueue`。
3. **缩略图缓存**：`%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache*.db` / `iconcache*.db`。被资源管理器占用的跳过并提示。
4. **回收站**：用 Shell COM 统计大小，`Clear-RecycleBin -Force` 清空。**默认不勾选**，说明写明「永久删除、不能恢复」。

交互与第一阶段一致：进入页面自动扫描，逐项显示大小与说明，勾选后清理，清完重扫，按前后差值显示「已释放 X」。两组各自独立，互不影响。被占用的文件在提示行汇总「有 N 个文件正在被使用，已跳过」。

扫描分两步：先取清单把行渲染出来，再并行逐项算大小——算好的就地替换，没算完的显示「计算中…」，期间清理按钮显示「计算中…」并禁用。原因是本机 `%TEMP%` 达 10.7 GB，一次递归统计约 7 秒，若整组等算完再渲染，页面会长时间停在「正在计算占用…」。清理时直接拿页面上已算出的大小当「清理前」基准，不再重扫一遍；清理后只重扫一次用于刷新与算释放量。

## 4. 必要依赖

无新增依赖。沿用项目既有的 PowerShell 子进程调用；不需要管理员权限、不弹 UAC。

## 5. 验收条件

1. 「空间」页出现两组：「灵动岛的缓存」「系统垃圾」，各自有独立的勾选、提示行与清理按钮。
2. 系统垃圾四项显示实际大小；回收站默认未勾选。
3. 清理临时文件后重扫大小下降；被占用的文件不导致整体失败。
4. 缩略图缓存被占用时，提示行说明跳过了多少个文件。
5. 清空回收站后重扫为 0（不可恢复，交付时由用户确认）。
6. 点其中一组的清理按钮，另一组的选择与结果不受影响。
7. 传入白名单外的 id 被忽略，不会删除任何额外路径。
8. 反复点击任一组的清理按钮，按钮与提示区不发生位移（沿用第一阶段的固定占位与锁宽）。
9. 进入页面后清理项立即出现；某一项（如 `%TEMP%` 达 GB 级）还没算完时，该项单独显示「计算中…」，其它项照常出数，全部算完后按钮才恢复可点。

## 6. 不做什么

1. 不做需要管理员权限的项目：Windows 更新缓存、传递优化缓存、`Windows.old`、系统级 WER。
2. 不重启资源管理器、不结束任何进程。
3. 不扫描或删除文档、下载、桌面、图片等用户目录。
4. 不做定时自动清理、不做后台扫描。
5. 不做「只清空回收站里的某几项」。
6. 不把系统垃圾移入回收站——那样不释放空间；这一组的删除就是永久删除（回收站本身除外，它是清空动作）。

## 7. 自检记录

环境：隔离实例，`--user-data-dir`、`LOCALAPPDATA`、`TEMP`/`TMP` 全部指向 `.tmp/space-e2e2` 下的假目录，CDP 9321。假数据：临时文件 5.3 MB（含 80×60 个小文件与子目录，让递归统计真的花时间）、崩溃转储 400 KB、WER 50 KB、缩略图/图标缓存 90 KB；另建 `outside/keep.txt` 作越界哨兵。

1. `npm run typecheck` — EXIT=0；`npm run build` — EXIT=0。
2. 页面出现两组「灵动岛的缓存」「系统垃圾」，各自独立显示大小、勾选与按钮；系统垃圾四项扫描结果与假数据一致（临时文件 5.3 MB、崩溃转储 450 KB、缩略图 90 KB），回收站显示真实回收站大小 1.16 GB 且默认未勾选。
3. 点「系统垃圾 → 清理选中项」后：临时文件、崩溃转储、WER、缩略图与图标缓存全部删除，回收站未动；提示「已释放 5.5 MB」；`outside/keep.txt` 保留。
4. 同一时刻「灵动岛的缓存」组的扫描结果、勾选与按钮状态完全不受影响。
5. 用 `share=None` 独占打开一个 300 KB 的 `locked.tmp` 再清理：文件保留、重扫临时文件仍显示 300.0 KB，提示「临时文件里有 3 个正在被其他程序使用，已跳过」——按文件锁跳过的分支生效。
6. 给 `cleanup:run('system', [...])` 传 app 组 id 与乱造 id（`update-cache` / `lyrics` / `../evil`）：`freedBytes=0`、无警告、哨兵文件仍在。
7. 逐项扫描（CDP 每 100 ms 采样一次）：+320 ms 时四项已渲染、全部为「计算中…」；+432 ms 崩溃转储与缩略图先出数；+647 ms 临时文件与回收站出数，按钮同时从「计算中…」变回「清理选中项」——慢项不再拖住整组。
8. 点清理到提示出现耗时 1299 ms（含清理后重扫四项），说明清理前没有再走一遍 `%TEMP%` 递归；数字逐项填入时行内文字不左右挪动（尺寸列锁 56 px、右对齐）。

1. **清空回收站**：会把本机真实回收站（1.16 GB）永久清掉，没有自测；只验证了大小统计（只读）。
2. 缩略图缓存被资源管理器真实占用的跳过分支：用假文件测了「被独占锁定的文件不删」，但没有在真实的 `thumbcache*.db` 上触发过。
