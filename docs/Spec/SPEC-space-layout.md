# SPEC：空间页布局统一（两块卡片）

- 创建：2026-11-20
- 分支：`space-layout`（从 `main` `7d27a01` 拉出）
- 前置：`SPEC-space-cleanup`、`SPEC-space-system-junk`、`SPEC-space-residue`、`SPEC-space-admin-cleanup`

## 1. 目标

空间页现在由四张独立的卡片组成（灵动岛缓存、系统垃圾、卸载残留、系统清理），每张自带标题、说明、按钮，视觉上「一块一块」。改成**两块**：

1. **灵动岛**：灵动岛自己的缓存与日志。
2. **系统**：系统垃圾、卸载残留、需要管理员三项，作为这张卡片里的三个小节，用细线分隔。

只改外观与排版，**不改任何清理行为、接口和数据结构**。

## 2. 修改范围

- `src/renderer/src/settings/SpaceSection.tsx`：两块卡片的组合方式；三个面板支持「作为卡片内的小节」渲染（标题降一级、去掉各自的卡片外框）。
- `src/renderer/src/settings/settings.css`：`.clean-group` 改为卡片本体；新增小节分隔与列表容器样式；去掉列表外层的 `.set-card` 描边。
- 文档：`docs/facts/功能清单.md` 第 16 节、`docs/状态.md`。

不改：`src/main/` 下任何文件、`src/shared/types.ts`、`preload`。

## 3. 预期行为

### 3.1 版面

- 页面从上到下只有两块带边框的卡片，卡片间距与页面其它页一致。
- 第一块标题「灵动岛」，一句说明后直接是清理列表、提示、合计与按钮。
- 第二块标题「系统」，说明之后依次为小节「系统垃圾」「卸载残留」「需要管理员」，小节之间用一条细线分隔；每个小节保留自己的列表、提示、合计和按钮。
- 卸载残留小节的「备份与撤销」留在该小节内，与小节内容之间也有细线分隔。

### 3.2 交互与行为

- 每一小节的勾选、扫描、清理、撤销、删除备份、UAC 提权全部保持现状，互不影响。
- 逐项扫描时的「计算中…」、按钮宽度锁定、提示区占位等既有防跳动处理不变。
- 键盘与屏幕阅读器的语义：卡片标题为三级标题，小节标题为四级标题；勾选项仍是 `role="checkbox"`。

## 4. 必要依赖

无新增依赖。

## 5. 验收条件

1. 空间页只出现两块卡片；「系统」卡片内部三个小节之间是细线而不是三张卡片。
2. 四个功能区的行样式（勾选框、名称、说明、尺寸）完全一致。
3. 每一小节的「重新读取 / 清理选中项」只作用于本小节；清理后提示位置不变、按钮不横跳。
4. 卸载残留的备份列表、撤销与两步确认照旧。
5. 第四组仍需管理员：扫描不弹 UAC，点清理才弹一次。
6. 其它设置页不受影响。

## 6. 不做什么

1. 不合并成一整张清单、不做统一操作栏：卸载残留要备份、管理员要提权，混在一次点击里需要额外规则，这次只解决「看起来碎」。
2. 不改文案含义（除小节标题与两句总说明）。
3. 不动功能逻辑、IPC、数据结构。
4. 不做主题/明暗色适配之外的新视觉体系，沿用现有配色与圆角。

1. `npm run typecheck` — EXIT=0；`npm run build` — EXIT=0。
2. DOM 结构：`.set-page` 下 1 张普通卡（标题「灵动岛」）+ 1 张 `clean-group-space` 卡（标题「系统」），系统卡内 `:scope > .clean-part` 恰为 3 个（系统垃圾 / 卸载残留 / 需要管理员）。
