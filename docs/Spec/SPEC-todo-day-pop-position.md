# SPEC：待办页日期浮层改为「输入行下方展开」

- 建立日期：2026-11-25
- 基线：`main` `9486f3e`
- 任务分支：`todo-day-pop-position`
- 背景：用户原话「你看代办页的，这个日历出现位置挡住上面 ui 了」。截图显示日期浮层把页头和「加一条」输入行整个盖住。

## 一、目标

1. 打开待办页的日期浮层时，页头（标题、完成度）和输入行（输入框、日期按钮、时钟、加号）保持可见。
2. 浮层从输入行下方展开，向下盖住列表区域，完整显示一个月（6 行日期）不出现滚动或裁切。
3. 岛的高度不变（沿用 2026-11-24「每页固定尺寸、不伸缩」的决定）。

## 二、修改范围

| 文件 | 改动 |
| --- | --- |
| `src/renderer/src/styles.css` | `.island.page-0 .todo-day-pop` 改为 `top: 38px` 定位；浮层内 `.cal` / `.cal-day` / `.cal-grid` / `.cal-weekday` 压紧到可放入的高度 |
| `docs/facts/视觉设计规范.md` | 同步待办页浮层规则 |

## 三、预期行为

1. 点日期按钮 → 浮层出现在输入行正下方 6 布局 px 处，水平居中，底部不越过岛内边距。
2. 浮层完整显示标题行、周标题、6 行日期；格子仍是圆角方块（不是圆）。
3. 页头与输入行始终可见、可点；浮层只覆盖列表。
4. 选日期后浮层收起，行为与现在一致（按钮高亮、提示行、占位符）。
5. 日程页（page-3）的月历不受影响，仍为 24×24 格子。

## 四、必要依赖

无新增依赖。

## 五、验收条件

- A1 `npm run typecheck`、`npm run build` 通过。
- A2 探针实测：浮层顶边 ≥ 输入行底边；浮层底边 ≤ 岛内边距内边界；浮层高度 ≤ 可用高度；`.cal-day` 屏幕尺寸为设计值。
- A3 回归：`e2e-todo-day-pick`、`e2e-todo-today`、`e2e-schedule` 相关脚本全过。
- A4 用户在本机预览版确认。

## 六、不做什么

- 不改岛高度、不做打开浮层时的窗口伸缩。
- 不改数据、IPC、添加逻辑。
- 不合并 `main`、不打包、不发版。
