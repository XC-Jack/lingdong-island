# SPEC：视觉设计规范

## 目标

把 VibeCoding UI 设计课视频里讲的「DESIGN.md 视觉规范」和博主网站清单，整理成本项目可执行的视觉规则文档。

## 修改范围

- 新增 `docs/facts/视觉设计规范.md`：本项目视觉规范正文。
- 更新 `AGENTS.md`：开工入口加一条「做界面前读视觉规范」。
- 更新 `docs/状态.md`：记录本次改动。

## 预期行为

1. 规范覆盖视频讲到的八个板块：整体气质、色彩系统、字体与排版、布局与响应式、形状、组件规范、层次与深度、设计约束。
2. 每个板块写本项目的实际取值，不用抽象形容词。
3. 新增或改界面时，AI 按这份规范执行；规范里的数值来自当前代码，不凭空发明。
4. 网站清单里能落地的部分（确定视觉方向、挑组件、写进 DESIGN.md 三步法）写进「执行步骤」。

## 必要依赖

- 视频 OCR 结果：`.tmp/frames_ocr.txt`、`.tmp/design_zoom_ocr.txt`（临时文件，仅作证据）。
- 博主网站：https://docs.starxops.com/articles/702c2907-62ef-4f68-84f4-024c4c6bc49c
- 视觉参数事实来源：`src/renderer/src/styles.css`、`src/main/index.ts`、`src/renderer/src/App.tsx`。

## 验收条件

1. 八板块齐全，每板块有可对照的具体值。
2. 文档通篇中文，分点只用 1.2.3. 一套序号，一条一行。
3. 读回文件内容与写入一致，没有乱码。
4. `AGENTS.md`、`docs/状态.md` 改动前已备份，改完读回。
5. git 提交哈希可查，未合并 main、未推送。

## 不做什么

- 不改现有界面的代码、颜色、尺寸。
- 不照搬视频或网站原文，不复制英文整段。
- 不引入新组件库，不改技术栈。
- 不把这份规范升级为全局规则（全局规则要改，先问用户）。
- 不处理转写失败问题（已放弃，OCR 够用）。
