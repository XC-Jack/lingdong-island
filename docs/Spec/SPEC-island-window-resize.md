# SPEC：切页时的窗口尺寸抖动（第二批：只留 1 次 setBounds）

- 建立日期：2026-11-22
- 基线：`main` `3981b62`
- 任务分支：`island-window-resize`
- 承接：`docs/Spec/SPEC-perf-no-sync-ps.md` 第六节「不做什么」里明确留给第二批的那条——**透明置顶窗口在每次切页时被连续改尺寸**。

## 〇、问题（[实测]，2026-11-22 本机与隔离实例）

切一次页（点圆点 / 翻页箭头 / 拖文件进岛）的时序：

1. 面板重挂 + `.island` 的 `width/height` CSS 过渡 220 ms 开始（岛自己先长/缩）；
2. `ResizeObserver` 去抖 80 ms → 约 300 ms 时把最终尺寸经 `island:set-expanded-size` 报给主进程；
3. 主进程 `animateTo()` 从**当前窗口矩形**再补间 **500 ms**（`setInterval(..., 8)`，即最多 62 次 `setBounds`）。

实测：一次切页触发 **9–19 次真实窗口 resize，跨 400–520 ms**。窗口是 `transparent: true` + `alwaysOnTop('screen-saver')`，每次改尺寸都要重新分配/合成整块 surface——本机（i5-12450H）帧间隔只到 33 ms 所以看不出来，弱 GPU / 驱动被 Chromium 拉黑（透明窗口退化成软件合成）的机器上就是「点一下切页，画面顿半秒」。这也是 `SPEC-perf-no-sync-ps` 之后唯一剩下的、与点击直接相关的卡顿源。

## 一、目标

**切页（内容尺寸变化）不再做窗口尺寸动画，一次到位。** 展开/收起的整体动画保留（用户 2026-11 明确要求过「220 太急、320 还是快」，最终定 500 ms），但把无效的超采样去掉：8 ms → 16 ms（125 fps 对任何显示器都没有意义）。

## 二、修改范围

只动 `src/main/index.ts`：

| 改动 | 说明 |
|---|---|
| `animateTo()` 的 `setInterval(..., 8)` → `16` | 500 ms 补间从最多 62 次 `setBounds` 降到约 31 次；观感不变（仍是 500 ms、仍是 easeOutCubic） |
| `animateTo()` 收尾那一下改成 `setBounds(computeBounds(isExpanded))` | 补间途中若内容尺寸上报过，收尾落到**最新**目标，不落在补间开始时的旧值 |
| 新增 `applyBoundsNow(isExpanded)` | 取消进行中的补间 + 直接把窗口放到目标矩形 |
| `island:set-expanded-size` 处理器 | 不再调 `animateTo(true)`，改调 `applyBoundsNow(true)`；**补间正在进行时**（展开/收起动画中）改成「从当前位置重起补间」，让剩下的帧拐向新尺寸（不重起会先长过头再缩回来，实测有 164→142 的抖动） |
| `island:set-collapsed-width` 处理器 | 同样处理：收起补间进行中时不再直接 `setBounds`（会先瞬移再被补间拉回，实测出现过 174→163→146→**76**→136），改成从当前位置重起补间 |
| `src/main/statusStore.ts` | 启动时 `void refreshAndBroadcast()` 预热一次状态读（异步、不阻塞）。这是本期回归时暴露的时序问题：状态读改成异步后，电量环在岛出现后还要等约 1.5 s 才来（实测 2.2 s），预热后约 1.2 s。不改产品行为，只让首次数据更早到 |
| `scripts/e2e-collapse-order.mjs` | R2d 改成「等电量环出现再断言顺序」（最多等 8 s）。断言内容不变（仍验证默认顺序），只是不再假定电量在第一帧就有 |

同时更新 `docs/facts/技术方案.md` 决策记录一行、`docs/状态.md`。

## 三、预期行为

1. 切页（内容变高/变矮）：窗口**只被改一次尺寸**，紧跟岛的实际尺寸；不再有「窗口追着岛跑」的 500 ms 过程。
2. 展开/收起：动画保留 500 ms，但实际 `setBounds` 次数约减半；收尾一定落在最新尺寸上。
3. 展开动画进行中若内容尺寸变了（例如展开同时切页），窗口不中途跳，等补间收尾一次到位。
4. 收起态宽度自适应（`island:set-collapsed-width`）本来就是直接 `setBounds`，不动。
5. 其余一切不变：窗口仍透明置顶、不做鼠标穿透、横幅预留区、避让、拖文件放大等都不碰。

## 五、验收条件

- A1 `npm run typecheck`、`npm run build` 通过。
- A2（隔离实例 CDP）切 4 次页（置物架 → 通知 → 音乐 → 待办）：**每次 `window.resize` 事件 ≤ 2**（改前 9–19），且事件跨度 ≤ 120 ms（改前 400–520 ms）；岛最终高 = 窗口高（±1）。
- A3 展开/收起：窗口从收起态到展开态仍然分多帧渐变（不是一帧跳变），最终尺寸 = `computeBounds(true)`；收起回到 `COLLAPSED_WIN_HEIGHT`。
- A4 回归：`e2e-head-order`、`e2e-banner-fit`、`e2e-bell-notify`、`e2e-shelf-view-pref`、`e2e-todo-today`、`e2e-collapse-order`、`e2e-avoid-mode`。
- A5 `scripts/perf-click-latency.mjs` 仍全过（不能因为改窗口逻辑把点击延迟又抬回去）。

## 六、不做什么

- **不把展开态窗口改成固定大尺寸**（`EXPANDED_MAX`）：那会让一块 540×315 的矩形挡住下面窗口的点击——`docs/facts/本机约束与踩坑.md` 已实测「透明区域的鼠标事件仍归窗口」，整窗穿透会让胶囊点不开，已决策不做。
- 不改 `.island` 的 CSS 过渡曲线/时长，不改去抖 80 ms（另一件事，先量本期效果）。
- 不合并轮询、不动音乐桥、不动渲染层组件结构。
- 不合并回 `main`、不打包、不发版（等用户决定）。

## 七、自检记录

### 7.1 命令与结果（[实测]）

- `npm run typecheck` → **EXIT=0**；`npm run build` → **EXIT=0**。
- 隔离实例 CDP（端口 9380/9381/9382，用完即关），用页面里的 `resize` 事件计数 + 前后 `innerHeight` 对比：

| 场景 | 改前 | 改后 |
|---|---|---|
| 切到置物架 | 9–19 次 resize，跨 400–520 ms | **1 次，跨度 0 ms**（窗口 156 = 岛 155） |
| 切到通知 | 同上 | **1 次**（窗口 244 = 岛 243） |
| 切到音乐 | 同上 | **1 次**（窗口 208 = 岛 207） |
| 切到待办 | 同上 | **1 次**（窗口 188 = 岛 187） |
| 展开（收起 → 待办页） | 补间 62 次 `setBounds`，高度序列出现过 240 再跳 188 | **18 次 resize、跨度 496 ms，序列单调** 78→103→…→186→187→188 |
| 收起（Esc） | — | **18 次 resize、跨度 508 ms，序列单调** 172→155→…→78→76，最终 76 |

- `node scripts/perf-click-latency.mjs` 仍全过：启动 694 ms、点击 P95 8 ms、`statusSnapshot` 真实读数。
- 回归（均通过）：`e2e-head-order` 14 过 / 0 败、`e2e-banner-fit` 8 过 / 0 败、`e2e-collapse-order` **22 过 / 0 败**、`e2e-bell-notify` 15 过 / 0 败 / 0 跳过、`e2e-shelf-view-pref` PASS、`e2e-todo-today` PASS、`e2e-avoid-mode` 15 过 / 0 败。

### 7.2 过程中发现并修掉的两个真实抖动（都是本轮引入补间重起机制后才暴露的）

1. **展开时「先长过头再缩回」**：补间按「起点 → 每帧现算的目标」插值，等真实尺寸在 ~300 ms 报上来时，前面的帧已经朝旧目标走出去了，后面几帧再往回走 → 实测 78→…→164→**142**→…→188。改成「重起补间（起点=当前矩形）」后单调。
2. **收起时闪一下 76 再弹回去**：`island:set-collapsed-width` 在收起补间途中直接 `setBounds(computeBounds(false))`，把窗口瞬移到最终收起尺寸，下一帧又被补间拉回中间值 → 实测 174→163→146→**76**→136。改成补间途中重起补间后消失。

### 7.3 未验证的范围

1. 打包版未测（本轮不打包）。
2. 只在 125% 缩放、i5-12450H 上看过；弱 GPU / 软件合成机器上的实际体感无法在本机复现——本轮只证明了「窗口尺寸变更次数从 9–19 次降到 1 次」，**没有**在真弱机上量过帧率。
3. 展开/收起补间仍可能因「真实尺寸晚到」而延长到约 600–800 ms（重起补间），主观是否偏慢没有真人评估。
4. 高刷新率显示器（120/144 Hz）下 16 ms 步进是否看得出阶梯，未测。
5. 「切页时窗口先到位、岛内容用 220 ms CSS 过渡长到目标」这段（约 100 ms 内窗口略大于岛）没有逐帧截图核对。
