# SPEC-us-040 通知页两级堆叠（应用堆叠 + 会话细分堆叠）

## 一、目标

通知页消息列表改为两级堆叠结构，减少重复消息刷屏：

1. **第一级（默认视图）**：按应用（app）堆叠——每个应用只显示一条组条目：图标 + 右上角数字（该应用的通知条数）+ 最新一条的标题/正文预览 + 时间。
2. **第二级**：点击组条目展开该应用内部列表；组内**再按会话（title）细分堆叠**——群的消息堆一起、个人的堆一起，每堆右上角显示数字与最新一条预览；点击会话堆展开为具体条目。
3. 堆叠**只改显示方式**：已读水位、清空、实时刷新、点击直达（具体条目上）全部语义不变。

用户原话（m05610）：「首先就是先应用堆叠，然后点进去后，又再细分堆叠，群的堆群，人的堆人」。

## 二、修改范围

- `src/renderer/src/App.tsx`——NotifyPanel 渲染逻辑：新增分组计算（纯函数）与两级展开状态；具体条目的渲染/点击直达/时间显示复用现有 JSX。
- `src/renderer/src/styles.css`——组条目样式（图标右上角计数徽标、展开缩进、会话子组样式）。
- `scripts/e2e-notify-group.mjs`——新建：堆叠结构、计数、两级展开、数据还原断言。

不改动：主进程 notifyStore.ts（数据结构/水位/推送不动）、preload、已读与清空逻辑、通知横幅。

## 三、预期行为

1. 默认列表：同一 app 的多条通知合并为一条组条目，右上角数字 = 条数；组内按到达时间取最新一条做预览。
2. 只有一条通知的应用显示为普通条目（数字徽标可省略或显示 1——实现取「无徽标」）。
3. 点击组条目 → 展开该应用的会话分组列表（按 title 分组，同样的计数/预览样式）；再次点击 → 收起。
4. 点击会话子组 → 展开该会话的具体条目（逐条显示，保留现有图标/时间/点击直达）；再次点击 → 收回会话条目层。
5. 未读数字（页面顶部计数）仍按通知条数累计，不受堆叠影响。
6. 「清空」与实时刷新行为不变；新通知到达时列表自动重拉并保持当前展开状态（按 app/title key 保留）。
7. 组条目排序按最新通知时间倒序；会话子组同理。

## 四、必要依赖

无新依赖。复用：现有 NotifyItem 数据（app/icon/title/body/arrival）、图标缓存、file:// 图标加载、现有 e2e 基建（CDP 9321 + dev electron）。

- [实测] 回归：e2e-notify-live（实时刷新）、e2e-notify-clear（清空）、e2e-collapsed-todo、e2e-code-hint 全 PASS。
- [实测] typecheck / build PASS。

## 六、不做什么

- 不做收起态胶囊上的 App 角标（用户 m05606 已否决该方案）。
- 不动主进程数据结构、SQL、水位与横幅逻辑——堆叠是纯渲染层显示变换。
- 不做跨会话搜索、按日期分组、手动置顶等附加能力。
- 不区分「群聊 vs 私聊」的数据标签——wpndatabase 里没有该信息，title 堆叠天然等价（同一群/同一人的 title 相同）。
- 展开状态不持久化（重启后回到默认堆叠视图）。
