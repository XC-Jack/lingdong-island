# SPEC 目录

每次开发任务（一个新版本，或一个明确的开发任务）在**动手写代码之前**，在这里建一份 SPEC。

- 规则见 [`../工程规则.md`](../工程规则.md) 第二节「SPEC 先行」。
- 开发与独立验收使用**同一份 SPEC**，分别填写「自检记录」和「验收记录」。
- SPEC 通过链接引用 `../facts/` 的产品事实，不复制整套产品设定。

当前还没有确定的开发任务，本目录只有这份说明。

## 模板

新建文件命名：`SPEC-<任务名>.md`，任务名与 Git 分支同名。

```markdown
# SPEC-<任务名>

- 建立日期：
- 对应基线提交：<main 上的哈希>
- 任务分支：<分支名>
- 关联用户故事：US-xxx（见 ../facts/用户角色与用户故事.md）
- 关联事实文档：

## 一、目标

这次要达成什么。一两句话说清，不写实现细节。

## 二、修改范围

会动哪些文件/模块；明确列出**不动**什么。

## 三、预期行为

用户能看到/感受到的变化。用「点哪里 → 会看到什么」描述。

## 四、必要依赖

新增依赖、需要的外部条件；没有就写「无」。

## 五、验收条件

可逐条核对的清单，每条都要能被第三方验证：

- [ ] 条件 1
- [ ] 条件 2

## 六、不做什么

本次明确排除的范围，防止范围蔓延。

## 七、自检记录

| 日期 | 执行内容 | 结果 | 未验证部分 |
|---|---|---|---|

## 八、验收记录

| 日期 | 验收人/会话 | 针对提交 | 逐条结论 | 总体 |
|---|---|---|---|---|
```
